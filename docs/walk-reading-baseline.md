# 산책 열람 기준과 복원 범위

2026-09-13 · APP #365 · 신규 측정 연결 전 1번 작업.

#336·#338·#342·#343·#353의 기록 탐색과 #357의 배속, 사용자가 실기기에서 확인한
#360의 서랍 동작을 다음 작업의 기준으로 삼는다. 새 UI나 측정 정책을 추가하는 작업이 아니다.
사용자는 장면을 읽는 중이며, 위치 근거와 집계 상태는 그 열람을 뒷받침한다.
장면 본문에 기록/관측 시각과 진단 정보를 반복해서 넣지 않는다.

## 유지할 행동

| 행동 | 반드시 유지할 결과 |
|---|---|
| 정상 장면 선택 | 해당 방문의 보행 범위를 강조한다. 생략된 정상 관측도 처리 근거를 따라 연결한다 |
| 제외 이동의 장면 선택 | 확인된 보조 경로를 해당 스타일로 강조한다. 보행 합계는 늘지 않는다 |
| 공백 선택 | 번호 없는 회색 `–` 항목과 선택 전용 점선으로 전후 관계를 읽는다. 거리·방향·장면 위치를 생성하지 않는다 |
| 지도 표식 선택 | 선택과 본문만 바뀐다. 카메라 명령·고정 여백·서랍 높이는 바뀌지 않는다 |
| 목록/화면 밖 장면 선택 | 선택한 위치로 명시적으로 이동한다. 현재 서랍 높이는 유지한다 |
| 전체 기록/보행 중심 선택 | 카메라 범위를 바꾼다. 장면/경로 데이터를 끄지 않는다 |
| 서랍 조작 | 최초 중간 높이, 탭만 보기/중간/펼침의 세 정착점을 유지한다. 본문과 목록은 중간 높이에서 독립적으로 스크롤한다 |
| 손잡이/탭/뒤로 가기 | 버튼은 중간↔펼침, 접힘에서는 중간으로 간다. 같은 탭은 접힘에서만 중간으로 올린다. 뒤로 가기는 한 단계 내린다 |
| 재생 중 접기·재열기 | 배속과 재생 위치·진행 상태를 유지한다. 공백에서는 커서를 숨기고 확인 위치에서 다시 표시한다 |
| 다른 탭/장면 선택 | 기존 규칙대로 재생을 멈추고 새 선택으로 전환한다. 같은 탭 재선택은 초기화하지 않는다 |
| 늦은 자료/장면 갱신 | 준비 전에는 기존 정상 읽기를 유지한다. 오래된 원본·장면 revision·계정 generation의 결과가 현재 선택을 덮지 못한다 |

지도 크기와 카메라 배치 여백은 서랍의 실제 가림 영역과 별개다. 선의 의미는 선택 시에도
유지하며, 보기 편하게 나눈 범위가 원본·보행거리·실제 단절 위치를 바꾸지 않는다.
[잠긴 디자인](design-locks.md)의 기존 색·지도 규칙과 함께 적용한다.

## 조합 검증

검증용 합성 기록에는 같은 길의 왕복 보행, 보행 제외 관측, 경로 공백과 독립 핀,
위치 없는 사건을 함께 넣는다. 개인 기록이나 외부 API에 의존하지 않는다.

`WalkReadingBaselineUiTest`는 실제 검토 화면의 reader→대응 계산→표현→선택 콜백을 사용한다.
네이티브 지도만 테스트 표면으로 바꾼다. 다음을 한 화면의 연속 동작으로 확인한다.

1. 목록에서 정상 장면 선택 → 보행 강조, 중간 높이 유지.
2. 지도에서 제외 이동 장면 선택 → 보조선/방향 강조, 카메라와 높이 유지.
3. 지도에서 공백 선택 → 선택 안내선 표시, 카메라/여백 유지.
4. 전체 기록 → 16배속 선택 → 재생/일시정지 → 공백 시점 탐색 → 안내선과 커서 없음.
5. 서랍 접기·같은 탭 재열기 → 배속·일시정지 유지 → 확인된 제외 이동 시점에서 커서 재표시.
6. 다시 지도 장면 선택 → 재생 커서 해제, 장면 강조. 지도는 한 번만 생성된다.

자동 진행은 `WalkDiaryCompactDrawerTest`에서 별도로 통제한다. 16배속의 기록 시점을
16초(보행)→32초(공백)→64초(보행 재개)로 진행시키며, 접힌 동안에도 시간이 흐르고
공백에는 커서/관계 안내선이 없으며 재열기가 재생을 초기화하지 않는지 확인한다.
시간을 직접 진행시키는 테스트이므로 실제 기기의 ticker 배율 측정과 구별한다.

기존 `WalkRecordOverviewUiTest`는 화면 밖 장면과 지연된 visibility 응답을,
`WalkDiaryReadViewTest`는 원본/장면 준비·실패·계정 generation을 검증한다.
`WalkDiaryCompactDrawerTest`의 본문/목록 끝까지 스크롤·버튼·드래그·작은 화면 검증도 함께 유지한다.

## 현재 유지와 복원은 다르다

| 상황 | 현재 구현의 범위 | 보장하지 않는 것 |
|---|---|---|
| 같은 화면에서 접기·재열기 | 장면/공백/재생 선택, 배속, 본문 읽던 위치, 지도 유지 | 앱 종료 후 영속 복원 |
| 같은 입력/장면의 늦은 갱신 | 준비된 읽기 재사용, 선택 ID와 높이 유지. 삭제가 확정된 장면만 해제 | 다른 측정의 구간 번호를 그대로 사용 |
| saved state가 있는 화면 재생성 | 장면 ID·배속·정착한 서랍 높이와 마지막 명시적 카메라 요청의 저장/복원 | 재생 시점, 선택한 공백/통과/구간, 읽던 탭의 완전한 복원 |
| 새 경로로 실제 교체 | 장면 ID를 보존해 새 근거로 대응. 다른 선택은 전체 보기로 전환하고 재생 정지 | 이전 재생 시점/구간의 자동 이식 |
| saved state 없는 새 진입 | 중간 높이의 장면 목록과 기본 보행 보기에서 시작 | 이전 화면의 장면·배속·스크롤 복원 |
| 앱 완전 종료 후 재진입 | 저장 기록을 다시 읽는 기존 흐름 | 열람 위치를 별도 영속 저장해 복구하는 기능 |

`StateRestorationTester`는 Compose saved-state 복원과 비동기 경로 준비를 함께 거친다.
검토 화면의 선택 장면 재연결·서랍 정착점·카메라 요청, 배속 유지와 자동 재생 금지를 확인한다.
새 composition 검증은 saved state가 없는 진입이다. 두 테스트 모두 Android 프로세스 종료,
Room 재개방, 인증 복원, 서버 재조회 전체를 실행했다는 뜻은 아니다.

`WalkDetailDataUiTest`에서는 검토 화면이 아닌 제품의 `WalkDiaryMapForAccount`도 재생성한다.
주입한 source의 재조회를 보류한 동안 접힌 높이를 유지하고, 재조회 후 저장된 장면을 다시
연결해 탭으로 열 수 있는지 확인한다. 저장소와 네트워크는 이 테스트의 범위 밖이다.

카메라 저장은 `DiaryMapNavigation`의 **마지막 명시적 이동 명령**이다. 손으로 이동/회전/
확대한 최종 SDK 카메라 위치를 저장한 것이 아니다. 재생성 후 정확히 같은 지도 구도를
보장한다고 보고하지 않는다. 본문 스크롤도 같은 화면에서의 유지와 재조회 후 복원을
구별하며, 후자는 로딩/장면 구성 변화까지 포함한 후속 기준으로 남긴다.

## 후속 복원 구현의 완료 기준

아래는 이번 PR의 구현 완료 항목이 아니라 신규 측정 연결과 함께 적용할 계약이다.
현재 재생 시점이 사라지는 것을 테스트에서 의도한 UX로 잠그지 않는다.

- 소유자·산책·원본/측정 근거가 맞는지 확인한 뒤 장면 또는 기록 시간 주소를 복원한다.
  계정 전환/로그아웃/기록 삭제에는 이전 상태를 적용하지 않는다. 같은 계정의 새 로그인도
  진행 중 비동기 응답은 별도 generation으로 격리한다.
- 화면 재생성과 앱 완전 종료 후 재진입을 따로 검증한다. 잠깐 나갔다 돌아오는 경우에는
  기존 lifecycle의 일시정지 정책을 따른다. 어느 복원에서도 재생을 자동 시작하지 않는다.
- 같은 근거의 장면은 해당 장면으로, 재생은 이전 시간 주소와 배속을 가진 **일시정지**로 복원한다.
  공백 속 시간은 위치 없는 선택으로 복원한다. 이전 커서 좌표나 안내선으로 위치를 채우지 않는다.
- 측정 변경 시 원본 사건·관측 주소와 epoch/시간 근거로 다시 대응한다. 옛 구간 번호나 공간
  최근접을 빌리지 않는다. 대응 불가 시 재생 정지와 장면 목록/기록 전체 접근을 유지한다.
- 저장 대상은 작은 열람 주소이며 경로 전체나 예전 binding이 아니다. 경로 자료를 준비한 뒤
  현재 결과에 주소를 해석한다. 카메라 구도/서랍/본문 위치도 현재 화면과 내용에 맞게 검증한다.
- 실제 앱에서 종료→상세→재생→백그라운드 복귀, 시스템 재생성, 프로세스 재시작을 각각 확인한다.
  원본/장면 재조회 지연, 삭제, 계정 변경, 같은 장소의 다른 방문, 긴 기록을 포함한다.

신규 motion 기록 한 건의 연결은 전체 연결의 첫 기준이다. 그 기록에 존재하지 않는
GPS 공백·왕복·먼 보행 재개까지 실기기 검증 완료로 묶지 않는다.

## 검증 기록

이 PR은 화면/저장/측정 제품 코드를 변경하지 않는다. 새로 APK를 설치하거나 사용자 확인이
끝난 서랍을 다시 조정하지 않는다. 자동 검증의 명령·빌드와 실행 결과는 PR #365에 기록한다.
이전 실기기 확인은 [#353 최종 결과와 #360](walk-record-overview.md)에 날짜·빌드별로 남긴다.

2026-09-13 최종 실행: `:app:assembleDebug` 및 관련 **13개 클래스 87개 테스트 통과**
(실패/오류/건너뜀 0). `walk-record-review.init.gradle`, arm64-v8a, `walk-review-365`를 사용했다.
새 테스트는 5개이며, 기존 접힘 중 재생 테스트에는 공백 통과와 재개 검증을 보강했다.
초기 조합/새 진입 테스트의 캡처 대기 실패는 카메라 명령 및 Compose `SideEffect` 완료를
기다리도록 수정했다. 화면/측정 제품 코드는 바꾸지 않았고 최종 87개를 한 실행에서 확인했다.

새 검증을 좁혀 재실행하는 기본 명령:

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests '*WalkReadingBaselineUiTest' --tests '*WalkDetailDataUiTest' --tests '*WalkDiaryCompactDrawerTest'
```
