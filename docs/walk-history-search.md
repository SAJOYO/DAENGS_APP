# 산책 기록 검색

산책 기록은 기록이 없어도 검색창, 기간, 계절, 출발 날씨 조건을 보여준다.
검색 결과 영역만 로딩/오류/첫 기록 대기/조건 결과 없음/페이지 목록으로 바뀐다.
강아지 조건은 기존처럼 등록된 아이가 둘 이상일 때 표시한다.

## 조건

- 제목·메모: 현재 읽을 수 있는 저장된 일기 대표 제목과 삭제되지 않은 사용자 메모에 대한 포함 검색.
  NFC 정규화와 대소문자 무시를 적용하며 `%`와 `_`도 일반 문자다. 공백만 입력하면 조건 없음이다.
  JSON 키, 출처, 근거 문구, 장면 본문, 액션 코드에는 매치하지 않는다.
  생성 제목이 없는 날짜 기본 제목은 기간 조건으로 찾는다. 검색 시 LLM을 호출하지 않는다.
- 날짜: 산책 시작 시각을 기기 시간대로 변환한 날짜. 선택한 처음/마지막 날짜를 모두 포함한다.
  달력 선택기의 UTC 날짜 표현을 실제 산책 시간대로 잘못 해석하지 않는다.
- 계절: 3–5월 봄, 6–8월 여름, 9–11월 가을, 12–2월 겨울. 날짜와 같은 기준이다.
- 출발 날씨: 저장된 WMO 코드의 맑음/흐림·안개/비/눈/정보 없음.
  없는 코드와 알 수 없는 코드는 정보 없음이며 맑음으로 추정하지 않는다.
- 항목 사이 AND, 한 항목 안 다중 선택은 OR. 빈 선택은 전체다.
- 지역, 의미 검색, 장면 선정/내용 생성 LLM, 누적 브러시는 별도 범위다.

## 조회와 갱신

기존 소유 계정·종료·강아지 조건과 `(시작 시각 DESC, 세션 ID DESC)` 커서 순서를 유지한다.
후보를 작은 묶음으로 읽고 날짜/계절/날씨를 먼저 적용한다. 키워드가 있으면 해당 후보의
제목·메모를 트랜잭션에서 추출해 검사한다. 현재 페이지의 다섯 행만 검색하지 않는다.
다섯 개의 유효 결과와 다음 페이지 확인용 한 개를 채울 때까지 후보 조회를 이어간다.

제목은 목록 표시와 같은 원본을 사용한다. 준비/공개 행이 없는 기존 산책의 분석 제목은
`storyboardAnalysisView` 검증을 통과해야 검색되며, 메모 변경으로 무효가 된 제목을 되살리지 않는다.
새 공개 정책을 사용하는 산책은 준비 중에는 제목을 숨기고, 공개 후에는 확정된 보드 제목을 쓴다.
메모 변경·동기화 ACK로 공개 제목을 버리거나 늦은 AI 제목으로 바꾸지 않는다.
직접 남긴 메모는 두 경우 모두 동기화 전에도 검색된다. 자세한 기준은
[일기 공개 정책](walk-diary-publication.md#사용자-수정과-호환성)을 따른다.
별도 검색 복제본/DB 스키마/마이그레이션을 만들지 않아 이전 기록도 원본에서 바로 검색된다.
세션·메모·사진·분석·공개 상태 변경을 관측해 결과를 갱신한다. 계정 변경과 삭제에 대한 기존 검증을 유지한다.

필터에 탈락한 후보는 GPS를 읽지 않는다. 키워드 매치가 희소하면 과거 제목·메모를 여러 묶음
읽을 수 있다. 이는 전문 검색 인덱스가 아니며 대량 기록의 검색 지연은 향후 실측 대상이다.
전체 개수를 얻기 위해 모든 GPS를 계산하지 않는다. 결과가 있는 경우 페이지 번호와 이동만 표시한다.

## 상태와 화면

조건이 바뀌면 첫 페이지와 처음 스크롤로 초기화한다. 상세를 열었다 돌아오거나 화면 상태를
복원하면 검색어·조건·페이지·스크롤을 유지한다. 삭제로 현재 페이지가 비면 이전 페이지로 돌아간다.
키워드 입력은 250ms 지연 후 조회하며 이전 조회는 취소한다.
결과가 없을 때 전체의 유효 기록 한 건 여부를 확인해 첫 기록 대기와 조건 결과 없음을 구분한다.
오류와 로딩에서도 조건을 편집하고 초기화할 수 있다. 가짜 기록을 사용자 저장소에 넣지 않는다.

## 대상 검증

실제 Room을 사용하는 검색/페이지/소유 계정/메모 변경·삭제/제목 갱신 테스트와 Compose의
빈 상태 필터 조작/날짜 창/상세 복귀/상태 복원/조건 변경 후 페이지 초기화를 검증한다.
UI 테스트 이미지는 합성 자료이고 실사용자의 산책 기록이 아니다.

2026-09-07: 대상 34개 테스트를 검증했다. 첫 실행의 화면 테스트 한 건에서 Compose 구독 해제 전
테스트 DB를 닫는 정리 순서 오류가 발생했다. RuleChain으로 정리 순서를 수정하고, 필터 색과 날씨
표시를 조정한 뒤 영향받은 화면 10개 테스트를 재실행해 모두 통과했다. 나머지 조회 관련 24개도 통과했다.

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests '*WalkHistorySearch*' --tests '*WalkHistoryTest' --tests '*WalkHistoryThumbnailTest' --tests '*WalkDiaryTitleTest' --tests '*WalkDiaryReaderTest' --tests '*WalkDiaryMapScreenTest' :app:assembleDebug
# 화면 수정 후 해당 경계만 재검증
.\gradlew.bat :app:testDebugUnitTest --tests '*WalkHistorySearchScreenTest' --tests '*WalkDiaryMapScreenTest' :app:assembleDebug
```

Debug APK 빌드 성공. Pixel 에뮬레이터 설치 Success, 실행 Status: ok 및 설치 APK와 빌드 출력의
SHA-256 일치를 확인했다. 실제 빈 기록 화면에서 계절 메뉴 열기 → 가을 선택 → 닫기 → 초기화를
조작했다. 기기에는 실제 산책이 없어 결과 목록의 실기기 확인은 남아 있다.
`app/build/outputs/walk-history-{empty,results,no-results}.png`는 테스트 렌더이고,
`app/build/outputs/walk-history-pixel.png`는 실제 에뮬레이터 캡처다.
