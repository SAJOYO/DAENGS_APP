# 지난 산책의 지도 탐색

첫 제품 구현은 홈 → 지난 산책 안에서 실제 저장된 산책과 장면을 함께 읽는 화면이다.
Geo의 합성 실험 페이지를 앱에 넣지 않으며 debug/release 공통 `main` 소스셋에 둔다.

## 진입과 조작

- 지난 산책에서 목록/지도를 전환한다. 날짜 목록에서 한 산책을 고르면 그 산책의 지도·장면을 연다.
- 강아지·계절·강수 조건을 목록과 지도에 함께 적용한다. 같은 축은 OR, 축 사이는 AND다.
- 계절은 한국 시간의 산책 시작일이다. 날씨는 당시 저장한 WMO 코드로만 분류한다.
  누락·미지원 코드는 정보 없음이다. App 원본에는 혼합 강수를 명시한 필드가 없어 해당 칩은 제공하지 않는다.
- 지도에서는 좌표가 같은 기록들을 하나의 표시로 묶어 시간순으로 열 수 있다.
- 카드의 이전/다음으로 장면을 바꾸면 선택한 산책의 전체 경로도 바뀐다.
- 원본 산책은 기존 상세·사진·기록 편집·스토리보드 검토로 연결한다.
- 위치 없는 장면은 별도 목록으로도 볼 수 있다. 자동 장면의 거리나 시각만으로 좌표를 추측하지 않는다.
- 위에는 지도, 아래에는 장면 목록 또는 카드가 자리한다. 카드가 지도를 덮지 않는다.

## 데이터 경계

`WalkHistory.finished()`의 계정별 종료 산책을 선택한다. `WalkDiaryReader`는 해당 세션의
Room 기록·사진·분석·검토본을 관측하고 `WalkDiary`의 읽기 모델로 변환한다.
세션 소유자와 종료 여부를 다시 확인하며 삭제된 세션은 제거한다.
저장된 분석의 신선도 판정은 기존 `storyboardAnalysisView`를 사용한다.
사용자 문구·숨김·원본 변경 재검토 상태는 그대로 따른다. 변경된 원본의 오래된 자동 장면은
현재 기록으로 다시 살리지 않는다. 사진은 자동 분석 장면으로 변환하지 않고 사진 항목으로 제공한다.

전체 GPS 상세는 선택된 산책에 대해서만 로드한다. 다른 산책은 기존 목록용 요약을 사용한다.
일시정지·GPS 단절은 기존 완료 경로 표현을 통해 유지한다.
DB 테이블·버전·마이그레이션·서버 요청 계약은 바꾸지 않고 검토본 관측 쿼리만 추가한다.

## 다음 연결

이번 단계에 누적 브러시는 없다. 현재 공간 일기 응답을 그대로 연결하면 Geo에서 합의한
관측 완전성 분모와 계절 조건, 선택 산책 식별자가 일치하지 않는다.
후속 Dev 계약에는 선택 산책/원본 버전, 관측 상태·계산 대상 수, 계절·강수 selector와
장면의 검증 가능한 좌표 연결이 필요하다. 그 결과를 같은 지도 배경에 넣고
가는 브러시·겹 수 중심 30% 혼합 농도로 표시한다.
현재 마커 묶음은 동일 좌표 기준이며 Geo 실험의 줌별 화면 거리 묶음도 후속 연결 대상이다.
자동 서술·익숙함 판정·지역 필터는 추가하지 않는다.

## 검증

변경 대상: 일기 읽기 모델·Room 관측 쿼리·지난 산책/지도 UI.
아래 대상을 나누어 실행해 총 22개 테스트를 통과했다.

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests '*WalkDiaryTest' --tests '*WalkDiaryReaderTest' --tests '*WalkDiaryMapScreenTest' --tests '*WalkHistoryTest' :app:assembleDebug
# 수정 뒤에는 실패/변경된 테스트 클래스만 다시 실행했다.
```

- WalkDiaryTest 6개: 한국 시간 계절 경계, 다견/OR/AND 조건, 날씨 누락, 사용자 문구/숨김,
  자동 장면의 좌표 추측 방지, 같은 위치의 세션 구분, 사진 원본 유지.
- WalkDiaryReaderTest 2개: 실제 Room의 검토본 갱신·세션 삭제, 소유 계정과 종료 여부.
- WalkDiaryMapScreenTest 3개: 장면 전환과 원본 이동, 필터 전체 동작, 360×640 영역의 지도·카드 배치.
- 기존 WalkHistoryTest 11개: 기존 산책 저장·계산·조회 회귀.

첫 실행에서 새 테스트 준비 함수 반환형을 수정했고, 이미지 캡처의 PixelCopy 시간 초과를
Robolectric View.draw 방식으로 해결한 뒤 해당 UI 테스트만 다시 통과했다.
`app/build/outputs/walk-diary-map-card.png`를 직접 확인했다. 이 이미지는 합성 테스트 장면과
지도 자리 표시자를 그린 Compose 배치 확인용이며 실제 Naver 지도·픽셀 화면은 아니다.

최종 main 코드의 debug APK 빌드가 성공했다. `app/build/outputs/apk/debug/app-debug.apk`.
에뮬레이터/실기기 설치, 지도 SDK 시각·성능 검증, dev 머지는 하지 않았다.
