# 미니룸 에셋 제작 워크플로

미니룸에 들어갈 가구·소품 PNG를 **직접 만드는** 방법.

> **현재 상태 (2026-08-25)**
> 방·소품·강아지는 전부 PNG 로 돌고 있다. 팀 다른 저장소
> (`frankie516c/dog-training-rag`)에서 만든 픽셀 아트 팩을 `tools/import_room_assets.py`
> 로 반입해 쓴다 — 자세한 건 [README](../README.md#그림은-어디서-오나) 참고.
>
> 그러니 이 문서는 **저쪽에 없는 소품을 우리가 새로 그릴 때** 보는 것이다.
> 아래 본문에 "지금 도형으로 되어 있다"는 식의 서술이 남아 있으면 도형으로 그리던
> 시절 이야기다. 격자에 맞추는 법·기준점 규칙·검증 방법은 지금도 그대로 유효하다.

---

## 0. 결론부터

반려동물 소품은 **직접 그리는 편이 빠르다.** 밥그릇·뼈다귀·방석·장난감 같은 건
무료 팩에 잘 없고(대부분 사람 가구 킷이다), 있어도 화풍이 안 맞아 어차피 손을 봐야 한다.

`docs/templates/iso-template-*.png` 를 밑에 깔고 그리면 격자에 바로 맞는다.
템플릿은 아래 명령으로 원하는 발자국 크기만큼 다시 만들 수 있다.

```
uv run tools/isoasset.py template --cols 1 --rows 1 --height 1.5
uv run tools/isoasset.py template --cols 2 --rows 2 --height 0.8
```

> 파이썬은 **uv 로 통일**한다 (팀 규칙). 스크립트 안에 의존성이 선언돼 있어서
> `uv run` 이 알아서 받아 쓴다 — 가상환경을 만들거나 따로 설치할 필요가 없다.
> uv 가 없으면 https://docs.astral.sh/uv 에서 설치.

3D 로 만들고 싶다면 아래 1번의 카메라 값대로 렌더하면 된다. 여러 방향(4장)이 필요하거나
조명을 일정하게 맞추고 싶을 때는 3D 쪽이 낫다.

## 0-1. 2D로 그리는 법 (실제 순서)

### 툴

**Figma 를 추천한다.** 무료, 브라우저에서 바로, 크기를 픽셀 단위로 정확히 지정할 수 있고
PNG 내보내기가 깔끔하다. 우리 아트는 납작한 파스텔 도형이라 벡터 툴이 잘 맞는다.

| 툴 | | |
|---|---|---|
| **Figma** | 무료 | **추천.** 정확한 수치 입력, 깔끔한 PNG 내보내기 |
| Photopea | 무료 | 브라우저 포토샵. 기울이기(skew)가 필요하면 이쪽 |
| Inkscape | 무료 | 벡터 + 기울이기 지원 |
| Affinity Designer | 유료(저렴) | 위 둘의 상위 호환 |
| Procreate | 유료(iPad) | 손으로 그리는 느낌을 원하면 |

> Figma 에는 기울이기(skew)가 없다. 하지만 **우리는 거의 필요 없다** — 아래 두 규칙으로
> 대부분 해결되고, 상자 모양은 펜 툴로 템플릿 안내선 따라 다각형을 그리면 된다.

### 준비

1. `docs/templates/iso-template-1x1.svg` 를 Figma 에 **드래그해서 넣는다**
   (SVG 라 선이 벡터로 살아있고, 레이어가 `footprint` / `reference-cube` / `anchor` 로 나뉘어 있다)
2. 템플릿 레이어를 **잠그고(Lock)** 그 위에 새 레이어에서 그린다
3. 프레임 크기는 그대로 둔다. **1x1 템플릿은 512x588 px**

### 이게 핵심 — 두 가지 규칙만 지키면 격자에 맞는다

**규칙 1. 바닥에 닿는 둥근 것은 "가로:세로 = 2:1 타원"**

바닥에 놓인 원은 화면에서 항상 2:1 타원이 된다. 밥그릇 테두리, 러그, 방석, 그림자 전부.
Figma 에서 원을 그리고 **높이를 폭의 정확히 절반**으로 입력하면 끝이다.
(폭 160 → 높이 80)

**규칙 2. 상자 모양은 "가로 2칸 갈 때 세로 1칸" 기울기**

템플릿의 파란 정육면체가 그 각도다. 펜 툴로 그 선을 따라 다각형을 그리면 된다.
화면 각도로는 26.57도.

**그리고 세로(높이)는 절대 기울이지 않는다.** 위로 곧게 올린다.
바닥면만 기울고 높이는 수직인 게 아이소메트릭이다.

### 예시: 밥그릇 만들기 (1x1)

1x1 템플릿(512x588)에서, 빨간 십자(기준점)는 **(256, 486) px** 에 있다.

1. **밑면** — 타원 폭 160 / 높이 80, 중심을 빨간 십자에 맞춤 → 바닥에 닿는 면
2. **테두리 윗면** — 같은 크기 타원을 **위로 36px** 올림 → 그릇 벽 두께가 생김
3. **안쪽 그늘** — 폭 110 / 높이 55 타원을 테두리 안에 넣고 어두운 색
4. **안쪽 바닥** — 폭 80 / 높이 40 타원을 조금 더 아래에, 밝은 색
5. 템플릿 레이어 **숨기기**
6. 프레임 선택 → Export → **PNG, 1x** → 배경 투명 확인

깊이감은 2번과 3번 사이 간격에서 나온다. 간격이 크면 깊은 그릇, 작으면 접시.

### 크기·기준점 숫자는 잴 필요 없다

**프레임을 그대로 두고 그리면**, `ArtBox` 값은 템플릿에 적힌 숫자를 그대로 쓰면 된다.

```
iso-template-1x1  ->  ArtBox size = (128, 147),  anchor = (64, 121)
iso-template-2x1  ->  ArtBox size = (192, 115),  anchor = (96, 89)
iso-template-2x2  ->  ArtBox size = (192, 134),  anchor = (96, 92)
```

물건이 프레임보다 작아서 투명 여백이 남아도 **아무 문제 없다.** 아이템마다 크기를
재고 기준점을 계산하는 것보다 훨씬 안전하다 (기준점 어긋나면 물건이 공중에 뜬다).

다른 발자국 크기가 필요하면:
```
uv run tools/isoasset.py template --cols 2 --rows 1 --height 1.2
```
실행하면 그 템플릿의 `ArtBox size` 와 `anchor` 를 찍어준다.

### 다 그린 뒤

1. PNG 를 `app/src/main/res/drawable-nodpi/` 에 넣는다 (파일명은 소문자·숫자·밑줄만)
2. 각도 확인: `uv run tools/isoasset.py check app/src/main/res/drawable-nodpi/내파일.png`
   → `타일 2.00:1 맞음` 이 나와야 한다
3. `ItemCatalog.kt` 에서 해당 줄을 `Shapes` → `Res` 로 교체 (6번 섹션 참고)
4. 실기기에서 격자에 앉는지 확인

### 만들 순서 추천

여기 적혀 있던 목록(밥그릇·물그릇·방석·뼈다귀·공·강아지집)은 **이미 PNG 로 들어와
있다.** 새 소품을 여러 개 만들 때의 요령만 남긴다.

하나 만들 때마다 갈아끼우고 실기기에서 확인하는 게, 다 만들고 한꺼번에 넣는 것보다
낫다. 첫 개에서 기준점 규칙을 몸에 익히면 나머지는 빠르다.

### 왜 2D 스프라이트 팩이 아니라 3D 킷인가

| | 2D 아이소메트릭 팩 | 3D 킷 리렌더 |
|---|---|---|
| 각도 | 원작자가 쓴 각도로 **고정**. 정확히 2:1이 아니면 격자에 안 맞아 전부 손보정 | 우리가 정한 각도로 렌더 → 타일에 픽셀 단위로 맞음 |
| 파스텔 리테마 | 아이템마다 픽셀 단위 리컬러 | 텍스처/머티리얼 한 번 고치면 전부 반영 |
| 방향 4장 | 각도별로 따로 그려야 함 | 모델 90°씩 돌려 렌더하면 끝 |

특히 **KayKit**은 모델 전체가 1024×1024 그라데이션 아틀라스 **한 장**을 공유해서,
그 텍스처만 파스텔로 바꾸면 전 아이템이 동시에 바뀐다. 우리 상황에 가장 잘 맞는다.

### CC0 킷 후보

전부 CC0 = 상업 이용·수정·재배포 자유, 출처 표기 불필요.

| 팩 | 규모 | 특징 |
|---|---|---|
| [KayKit Furniture Bits](https://kaylousberg.com/game-assets/furniture-bits) | 50+ | 단일 그라데이션 아틀라스 → **리테마 최적** |
| [Kenney Furniture Kit](https://kenney.nl/assets/furniture-kit) | 140 | 종류가 제일 많음 |
| [Quaternius](https://quaternius.com/) | 라이브러리 | 저폴리 전반 |

> **주의 1** — itch.io 팩은 라이선스가 제각각이다. 팩마다 확인하고, CC0 필터를 쓸 것.
> **주의 2** — 라이선스가 맞아도 **화풍은 안 맞는다.** 이 킷들은 채도 높은 저폴리라
> 시안의 부드러운 파스텔로 가려면 리컬러가 반드시 필요하다. 이건 건너뛸 수 없는 단계다.

### ⚠ Kenney 팩의 프리렌더 PNG는 그대로 못 쓴다 (실측 확인)

Kenney Furniture Kit에는 `Isometric/` 폴더에 **140종 × 4방향(NE/NW/SE/SW) = 561장**의
프리렌더 PNG가 들어있다. 방향 4장이 이미 있어서 솔깃하지만 —

**측정해보니 고도 45°, 타일 1.41 : 1 이라 우리 2:1 격자와 안 맞는다.**
(상자류 윗면 기울기 0.707, 그리고 원형 러그 바운딩박스 203×145 = 1.40 — 두 방법 일치)

세로로 눌러서 맞추면 바닥 발자국은 맞지만 **높이도 같이 눌려 원래의 58%로 납작해진다.**
가구가 눈에 띄게 낮아져서 쓰기 어렵다.

**대신 팩에 3D 모델이 같이 들어있다** (`Models/`, .obj/.fbx/.glb 각 140개).
이걸 블렌더에서 위 각도(고도 30°)로 다시 렌더하면 된다.

### 실험 결과: 각도를 맞춰도 Kenney 는 쓰기 어렵다

`TILE_RATIO` 를 1.4142 로 바꿔 Kenney 각도에 맞춰보고 실기기에서 확인했다.
**정렬은 완벽하게 맞았다** — 상자 밑변과 바닥 격자선이 나란해진다.
(2.0 일 때는 눈에 띄게 어긋난다)

그런데도 되돌렸다. 이유는 각도가 아니라 **내용물**이었다.

- Kenney Furniture Kit 은 **집 가구 킷**이다. 의자·사이드테이블·책장·휴지통은 있어도
  **밥그릇·뼈다귀·강아지집·장난감이 없다.** 넣어보니 강아지 방이 아니라 인형의 집이 됐다
- 화풍도 안 맞는다. 각진 저폴리 vs 우리 벽·문·창문의 부드러운 곡선
- 프리렌더 해상도가 낮다 (24~203px). 1080p 에서 1.5~2배 확대라 흐릿하다
- 덤으로 방 폭이 371dp -> 305dp 로 18% 줄어든다 (바닥이 깊어져서)

**교훈: 에셋 팩은 "각도가 맞는가"보다 "내용이 맞는가"를 먼저 봐야 한다.**
반려동물 소품이 들어있는 팩을 찾거나, 직접 만드는 편이 낫다.

`TILE_RATIO` 상수는 남겨뒀다 (`IsoMath.kt`). 나중에 1.41 각도 에셋을 쓰게 되면
그 한 줄만 바꾸면 방 전체가 따라간다.

## 1. 카메라 (제일 중요)

**직교(Orthographic) 카메라**여야 한다. 원근(Perspective)이면 타일마다 크기가 달라져서
격자에 안 맞는다.

| 항목 | 값 |
|---|---|
| 투영 | Orthographic |
| Yaw (Z 회전) | **45°** |
| **고도각(elevation)** | **30°** |
| **Blender 카메라 회전** | **X = 60°, Y = 0, Z = 45°** |

### 왜 30°인가

직교 투영에서 지면 위 축의 화면 기울기는 `sin(고도각)`이고,
따라서 **타일 가로:세로 = 1 / sin(고도각)** 이다.

| 고도각 | 타일 비율 | |
|---|---|---|
| 26.565° | 2.236 : 1 | |
| **30°** | **2.000 : 1** | ← 우리 격자 (64×32) |
| 35.264° | 1.732 : 1 | true isometric |
| 45° | 1.414 : 1 | Kenney 프리렌더가 이것 |

> **정정** — 이 문서 초판에 "고도 26.565°"라고 적었던 것은 **틀렸다.**
> 26.565°(= atan 1/2)는 2:1 타일의 **화면상 모서리 각도**이지 카메라 고도각이 아니다.
> 두 값을 혼동하기 쉬우니 주의. 카메라 고도는 **30°**다.

확인법: 1×1×1 정육면체를 렌더해서 **윗면 마름모의 가로:세로가 정확히 2:1**이면 맞다.
받아온 스프라이트는 아래 명령으로 바로 잴 수 있다.

```
uv run tools/isoasset.py check 받은에셋/*.png
```

## 2. 크기 — 기본 단위와 4배 저작

코드는 **기본 단위**로만 아트를 다룬다. 기본 단위에서 타일 한 칸은 **64 × 32**다.

- 아트 크기를 기본 단위로 먼저 정한다. 예: 강아지집 = 72 × 80
- 저장은 **4배**로: 72×80 → **288 × 320 px**

4배인 이유: 실기기(1080px 폭)에서 방이 화면 전체를 쓰면 타일 폭이 180px,
즉 기본 단위 1 = 약 2.8px이다. 4배로 저작하면 화면에서 **항상 축소**되므로 늘 선명하다.
확대되는 일이 없어야 뭉개지지 않는다.

## 3. 기준점(anchor) — 어긋나면 물건이 공중에 뜬다

기준점은 **물건이 바닥에 닿는 점**이고, 그림자는 그 점을 **중심으로** 그려진다.
여기를 잘못 잡으면 물건이 떠 보인다 (실제로 겪은 버그다).

| 종류 | 기준점 | 예 |
|---|---|---|
| 바닥에 눕는 것 | **밑면 타원의 중심** | 방석, 밥그릇, 담요, 뼈다귀 |
| 바닥에 서는 것 | **바닥에 닿는 맨 아랫점** | 화분, 강아지집, 공 |

렌더할 때 바닥면 중심이 어디인지 기록해두고, 그 좌표를 기본 단위로 환산해 코드에 적는다.

## 4. 저장 위치 — `res/drawable-nodpi/`

**반드시 `nodpi`.** 그냥 `res/drawable/`에 넣으면 안드로이드가 mdpi 기준으로 보고
디코딩할 때 기기 density만큼(이 폰은 **2.625배**) 자동 확대한다.
우리는 코드에서 직접 크기를 맞추므로 이중 스케일이 되고 메모리도 2.6배 낭비된다.
`nodpi`는 "density로 건드리지 마라"는 뜻이라 파일 픽셀 그대로 들어온다.

배경은 **투명(알파)** 필수. 그림자를 구우려면 부드럽게, 아니면 빼고 코드에 맡긴다.

## 5. 스프라이트 시트 (움직이는 것)

- 프레임을 **격자로 배치, 행 우선**(왼쪽 위 → 오른쪽 → 다음 줄)
- 모든 프레임 크기가 같아야 한다
- 코드에 넘길 값: `frameWidth`, `frameHeight`, `columns`, `frameCount`, `fps`

예시 파일: `app/src/main/res/drawable-nodpi/lantern_sheet.png`
(프레임 144×192, 4열, 4프레임, 4fps)

**힉스필드 강아지**는 영상으로 나오므로 → 프레임 추출 → 배경 제거(알파) → 격자로 합치기
순서가 필요하다. 그리고 **강아지는 아이소메트릭이 아니어도 된다.**
쿠키런 킹덤도 배경만 아이소메트릭이고 캐릭터는 정면/3-4 뷰 빌보드다.
작은 화면에서 진짜 아이소메트릭 캐릭터는 얼굴이 안 읽힌다.

## 6. 코드에 꽂기

`app/src/main/java/com/daengs/app/miniroom/art/ItemCatalog.kt`의 해당 줄만 바꾼다.

```kotlin
// 도형으로 그리던 시절
"plant" to ItemArtSpec.Shapes(
    ArtBox(size = Size(44f, 96f), anchor = Offset(22f, 88f)),
) { drawPlant() },

// PNG 로 교체
"plant" to ItemArtSpec.Res(
    ArtBox(size = Size(44f, 96f), anchor = Offset(22f, 88f)),
    resId = R.drawable.plant_01,
),
```

`ArtBox`(크기·기준점·차지하는 칸)만 그대로면 **정렬·터치판정·스냅·점유 계산은
한 줄도 안 바뀐다.** 도형 그리는 함수는 그냥 안 불리게 된다.

실제로 미니룸 전체를 PNG 로 갈아엎을 때 이 성질 덕을 봤다 — 아트만 바뀌고
배치·충돌 코드는 그대로였다.

스프라이트 시트는 `ItemArtSpec.Sheet`에 `resId`와 프레임 값들을 넣는다.

### 리컬러 (파스텔로 바꾸기)

받은 에셋을 우리 톤으로 바꾸는 건 스크립트 한 번이면 된다.

```
uv run tools/isoasset.py pastel 받은에셋/*.png -o app/src/main/res/drawable-nodpi
```

채도를 낮추고 명도를 올려서 파스텔로 만든다. 세기 조절:
`--sat 0.42`(낮을수록 연함) `--lift 0.16`(명도) `--warm 0.02`(따뜻한 쪽으로)

색상(hue)은 유지하므로 나무·천·금속 같은 재질 구분은 살아있다.

### 보간 방식

`filterQuality`로 아이템마다 고를 수 있다.

- **부드러운 파스텔 아트** → `FilterQuality.Medium` (기본값). 축소될 때 매끄럽다.
- **픽셀 아트** → `FilterQuality.None`. 최근접 이웃이라 도트가 살아있다.

섞어 써도 된다.
