# 산책 지도 속도 색상 v1

- 속도는 5단계, 경계는 0.4 / 0.8 / 1.2 / 1.6 m/s입니다. 각 경계 앞뒤 0.05 m/s에서 색을 섞고 2 m/s 이상은 마지막 색을 유지합니다.
- 기본 핑크, 빨강·파랑·보라 선택. 느린 쪽은 공통 검정입니다.
- 앱 산책 지도 상단 **색상 → 산책 지도 설정**에서 선택합니다. 지난 산책 지도에서도 같은 설정을 사용할 수 있습니다.
- 설정은 기기별 SharedPreferences에 저장하며, 산책 원본·거리·시간·업로드 payload는 바꾸지 않습니다. 계정 간·기기 간 동기화 설정이 아닙니다.
- `GET /app/walks/style-policy`는 앱 회원 인증이 필요한 읽기 전용 정책입니다. 기존 `/{walk_id}`보다 먼저 매칭합니다.
- 앱은 `assets/walk-style-v1.json`으로 즉시 그립니다. 설정을 열면 기존 인증 흐름으로 서버 정책을 읽고, 버전·구간·색상 수·형식을 검증한 뒤 캐시합니다. 이전 서버의 404·오프라인·잘못된 응답은 기존 정책을 유지합니다.
- 앱 asset과 dev의 `backend/tests/fixtures/walk-style-v1.json`은 같은 계약입니다. 정책을 바꿀 때 두 파일과 계약 테스트를 함께 갱신합니다.
- 색상은 화면용 좌표·시각에서 계산하며, 기록의 원본 GPS나 산책 판정 필터를 수정하지 않습니다. 0.5초 미만 / 10초 초과 간격, 비정상 속도는 회색(속도 불명)입니다.
- 인접 유효 구간의 속도를 경계에서 평균내고, 원래 선분 위를 최대 32파트로 나눠 부드럽게 칠합니다. 실시간에서는 새 점이 오면 마지막 인접 구간의 색이 보정될 수 있습니다. 경로 좌표를 평균내거나 곡선으로 이동시키지 않습니다.
- [NAVER MultipartPathOverlay](https://navermaps.github.io/android-map-sdk/guide-ko/5-7.html)를 녹화 세그먼트마다 하나씩 사용합니다. 일시정지·GPS 필터가 나눈 세그먼트는 서로 잇지 않습니다. 색 파트마다 네이티브 오버레이를 만들지 않습니다.

이번 변경은 속도 색상과 설정의 제품 반영입니다. GPS 재구성 알고리즘 변경, 실험실 체류 스탬프 정책 도입, DB 마이그레이션은 포함하지 않습니다.

두 PR은 각각 dev에 대한 작업 브랜치입니다. 서버 정책 배포 전 앱도 기본값으로 사용할 수 있고, 서버는 기존 앱의 계약을 바꾸지 않습니다. 새 API만 추가합니다. 테스트 결과와 빌드·실기기 검증 범위는 PR에 기록합니다. dev 레포의 dev 머지는 자동 배포이므로 별도 릴리즈 판단 후 진행합니다.

후속 체류 스탬프 정책은 [walk-stay-stamps.md](walk-stay-stamps.md)에 정리했습니다. 속도 색상 정책과 독립적으로 적용합니다.


## 지도 위 속도 범례

산책 화면(기록 중·완료)과 지난 산책 상세 지도에 `WalkSpeedLegend`를 항상 표시한다. 세로 산책 화면에서는 시간·거리 아래, 가로에서는 우측 상단 HUD 아래에 둔다. 지난 기록은 상단 버튼 아래다. 범례 높이를 지도 상단 여백에 반영해 전체 경로 맞춤에서 가려지지 않게 한다. 산책 경로를 표시하지 않는 대기 중 점령지 모드에서는 범례를 숨긴다.

범례는 `rememberWalkStyle()`로 네이버 동선과 같은 설정을 구독한다. `이동 속도 · m/s`, `0 · 느리게`, 범위 중간값, `상한+ · 빠르게`와 속도 미확인 색상을 표시한다. 기본 숫자는 0/1/2+이고 원격 정책의 상한이 바뀌면 함께 바뀐다. 색상 선택 후 지도를 다시 열 필요가 없다.

`speedScaleStops`는 실제 정책의 네 경계 양쪽(경계 ± blendHalfWidth)과 0/상한을 그대로 사용한다. 5개 색을 단순히 균등 간격으로 늘어놓지 않으므로, 경계 간격이 다르거나 전환 폭이 좁아도 동선의 속도별 색상과 범례가 일치한다. 설정창의 스펙트럼도 같은 계산을 사용한다.

검증 대상: 모든 테마와 비균등 원격 경계의 범례/동선 색상 일치, 색상 설정 후 범례 갱신, 지도 재진입 없는 원격 속도 상한 갱신, 기존 스타일 정책과 캐시. 실기기 지도 겹침/시각 확인은 별도이며 이번에는 설치하지 않았다.

검증 결과: `:app:assembleDebug` 성공. `WalkSpeedScaleTest`, `WalkStylePolicyTest`, `WalkStyleStoreTest`, `WalkColorSettingsTest`, `WalkSpeedLegendTest`를 선택한 단위 테스트 10개 통과(실패·오류·건너뜀 0).
