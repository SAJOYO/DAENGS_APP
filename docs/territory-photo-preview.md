# 점령 게임 3단계 — 현장 촬영과 페이크 사진 판정

[제작 계획](https://github.com/rkbuhtig/DAENGS_geo/blob/main/docs/explorations/walk/territory-production-plan.md)의
3단계이며 [지도 연결](territory-map-actions.md)을 이어간다. 구현 PR은 [#142](https://github.com/SAJOYO/DAENGS_APP/pull/142).
debug 앱에서만 연결한다. 실제 촬영 코드를 빌드했지만 연결된 Android 기기가 없어
카메라 동작·보행·진동·화면 배치의 실기기 검증은 남아 있다.

## 체험

1. 지도 키와 API 주소가 설정된 debug 앱에서 참여견을 고르고 산책을 시작한다.
   대표견은 기존처럼 첫 참여견이며 시도에 고정된다.
2. 점령지를 표시하고 장소에 접근한다. 빈 장소는 Pin으로 사진 없이 표시할 수 있다.
3. **영역표시 인증 촬영**을 누른다. 앱 내 CameraX 카메라에서 강아지와 현장을 찍는다.
   갤러리나 기존 사진 선택은 제공하지 않는다. 권한을 거절해도 산책은 유지되며,
   반복 거절했다면 앱 설정에서 카메라 권한을 허용한다.
4. 촬영 화면에서 테스트 결과를 고른다: 성공/부적합/통신 장애는 2초, 지연 성공은 15초.
   **사진 내용은 검사하지 않는다.** 사진 인증 연습임을 화면에 명시한다.
5. 저장 성공 뒤 지도에 복귀한다. 사진 확인 중에도 이동·다른 장소 점령·지도 표시 숨기기·
   산책 종료가 가능하다. 판정이 완료되면 점유 색과 인증 상태가 갱신된다.
6. 부적합은 같은 장소에 접근해서 **다시 촬영**, 통신 장애는 사진 인증 목록에서
   **판정 재시도**한다. 재시도는 같은 capture ID와 파일을 쓰고, 테스트 결과는 성공이다.
7. 다른 참여견을 첫 참여견으로 새 산책을 시작하면 기존 인증 영역의 탈취를 연습할 수 있다.
   확인 중·부적합·장애 동안에는 이전 점유자를 유지하고 성공 후 교체한다.

## 상태와 수명

- 카메라를 여는 것만으로 시도를 만들지 않는다. 셔터에서 세션·대표견·장소·최신 위치를
  재검증하고 기존 시도를 이어가거나 하나 만든다. 사진 저장 실패 시에도 같은 시도로
  다시 촬영할 수 있다. 빈 장소는 이 시점에 미인증 점유되며 촬영 실패가 이를 취소하지 않는다.
- 셔터의 로컬 접근 기준은 2단계와 같은 반경 20m, 위치 나이 10초, 거리+정확도 조건이다.
  지점의 표시용 거리나 지도 카메라에서 근거를 만들지 않는다. 온라인 canonical 증거는 후속이다.
- 파일은 전용 `cacheDir/territory-photos/<UUID>.jpg`에 저장한다. 기존 피부 사진용
  `capture.jpg`를 덮어쓰지 않는다. 파일별 capture ID가 별도로 시도에 연결된다.
- `TerritoryPhotoJudge`가 판정 경계이고 `FakeTerritoryPhotoJudge`는 내용 검사 없이 결과를 반환한다.
  `TerritoryPhotoQueue`는 지도 ViewModel 밖의 프로세스 범위에서 동작해 화면 이탈 후에도 처리한다.
- 성공/부적합/점유 충돌 시 사진 파일을 지운다. 장애는 재시도까지 보관한다. 캐시가 사라지면
  부적합 상태로 바꾸어 재촬영을 요청한다. 프로세스 종료 시 점유·대기열은 초기화되고 남은
  캐시 파일은 Android 캐시 관리에 맡긴다. 영속 outbox와 업로드는 4단계다.
- 인증 대기 중 다른 요청이 점유 버전을 바꾸면 임의 덮어쓰기 없이 확정 보류를 표시한다.
  충돌한 시도는 이 로컬 실험에서 다시 확정하지 않는다. 온라인 순서 정책은 아직 미정이다.
- 미인증끼리 무사진 경쟁, 시즌 점수는 구현하지 않는다. 인증된 동일 시도의 반복 탈취는 불가하다.

## 기기 없이 검증하기

Geo의 `scripts/spikes/territory_production_plan` 웹 실험은 합성 지도, 위치 조작, 샘플 촬영을
제공한다. Kotlin UI/CameraX를 브라우저에서 실행하는 것이 아니라 같은 계약을 JS로 재현한다.
APP·Dev와 같은 20단계 TSV를 사용한다. 파일 변경 시 세 저장소의 내용과 해시를 함께 확인한다.

```powershell
./gradlew.bat :app:testDebugUnitTest --tests '*Territory*' --tests '*WalkViewModelTest' --tests '*MapScenePolicyTest' :app:assembleDebug
```

타겟은 기존 지도/점령 회귀, 촬영 순간 재검증, 취소 전 무시도, 동일 시도 재촬영,
독립 파일 병렬 처리, 장애 재시도, 점유 충돌, 산책 종료/지도 비활성화 후 결과 반영이다.
실제 기기에서는 권한 거절/허용, 회전·백그라운드 복귀, CameraX 저장 성공/실패,
복수 장소 사진, 실제 반경 피드백과 세로/가로 배치를 추가 확인한다.
