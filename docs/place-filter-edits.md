# 자연어와 수동 검색의 공통 필터

2026-09-09, 5단계 #231. 수동 조건 #229 위에 연결하며 서버 계약은 [DAENGS_dev#362](https://github.com/SAJOYO/DAENGS_dev/pull/362)를 따른다.

## 사용 흐름

1. 현재 위치나 지도 기준으로 검색하고 업종을 1~6개 선택한다. 수동 `조건 선택`에서 공통 AND 조건·OR 묶음·주차 선호를 적용할 수 있다.
2. AI를 켠 뒤 조건을 입력한다. 기존 수동 조건을 해제할 필요가 없다. 위치·선택 반려견·검색 이름·기존 조건을 기준 상태로 보낸다.
3. 서버가 `ready`로 검증한 변경은 자동 적용한다. 기존 조건 변경에 확인이 필요하면 현재/변경 후 조건과 이름을 표시하고 `이 변경 적용`을 제공한다.
4. 미지원/모호/모순 요구나 오류면 기존 조건과 결과를 유지한다. 같은 엔진이 반환한 실행 결과만 채택하고 별도의 일반 검색을 다시 호출하지 않는다.
5. 적용한 조건은 언제든 수동 편집할 수 있다. 공통/분기의 업종 `in`·`not_in`, boolean 원자, 각 선호의 적용 업종을 보존하고 개별 삭제·수정을 제공한다. `확인 필요` 결과는 별도 버킷으로 표시한다.

## 상태와 네트워크

- 운영 factory는 `AuthenticatedPlaceFilterEditRepository`를 사용한다. 새 인증 API는 `/app/places/filter-edits`와 `/actions`다. 기존 발견 API 코드는 이전 연결과 테스트 호환을 위해 유지한다.
- `PlaceDiscoveryController`만 적용 조건·결과를 소유한다. `PlaceFilterAiCoordinator`는 진행 중인 제안/적용 요청과 안내를 소유한다.
- 기준 상태는 완료된 검색에서 캡처한다. 업종 전체보기를 임의의 6개로 잘라 보내지 않으며, 지원 조건 API나 위치를 아직 확인하지 못하면 요청을 안내한다.
- 수동 편집 화면을 열거나 검색 위치·반경·프로필·계정을 바꾸면 진행 중인 AI 요청을 무효화한다. 컨트롤러도 generation/전체 JSON 기준 상태를 비교하므로 취소를 무시하는 늦은 응답을 채택하지 않는다.
- 적용 실패 재시도는 같은 액션 UUID와 내용으로 수행한다. 401/403/409/410/422는 같은 요청 재시도 대상으로 노출하지 않는다. HTTP 왕복 전후에 현재 계정과 세션을 확인한다.
- 서버 상태·revision·액션·공간·반려견·미상 정책·상한을 비교한다. 원문 인용의 범위는 Unicode code point로 읽으며 UTF-16 위치로 자르지 않는다.
- 편집 세션은 서버에서 15분 뒤 만료된다. 앱 프로세스 재시작 뒤 미완료 제안 복원은 제공하지 않는다.

## 검증

수동/AI 공통 상태, 자동 적용과 확인 분기, 미지원 요구, 재시도 액션 동일성, 늦은 응답, 계정 변경, HTTP 인증, Python 실제 직렬화 fixture, `not_in` 편집, Compose 화면을 검증했다. 대상 63개 테스트와 debug 빌드가 통과했다. 테스트 fixture의 장소/반려견은 합성 데이터다.

Robolectric에서 `ai-unsupported.png`를 렌더해 미지원 안내와 기존 결과·수동 편집 진입이 함께 보이는지 확인했다. 실제 단말·Naver 지도·운영 API·Gemini 호출은 검증하지 않았다. 실호출 문장 정확도와 지연 검증은 다음 단계에 남긴다.

Backend와 Place의 새 API가 먼저 필요하다. 미지원 서버에서 이전 AI 검색으로 자동 전환하지 않는다. 이번 작업에서 배포하거나 단말에 설치하지 않았다.
