# 잠긴 디자인

**사용자가 실기기에서 보고 정한 화면 결정이다.** 에이전트(Claude · Codex · 그 밖의
무엇이든)는 여기 적힌 것을 **스스로 바꾸지 않는다.**

바꿔야 할 이유가 생기면 코드를 고치지 말고 **PR 본문 「남은 것」에 제안으로 적고
멈춘다.** 정하는 것은 사람이다 (`docs/collaboration.md` 1절 — 그림·화면 판단은
위임하지 않는다).

잠금은 테스트로도 걸려 있다 — `app/src/test/java/com/daengs/app/DesignLockTest.kt`.
**그 테스트가 깨지면 테스트를 고치지 말고 변경을 되돌린다.** 테스트를 고치는 것은
이 문서를 고치는 것과 같고, 그건 사람이 정한다.

> 왜 이런 문서가 있나: 같은 결정이 **서로 다른 사람·에이전트의 PR 에서 거듭 뒤집혔다.**
> 코드 주석만으로는 새 화면을 만드는 쪽이 못 본다 — 옛 화면에 적힌 주석이라서다.
> 그래서 화면 파일이 아니라 **여기 한 곳**에 모으고, 테스트로 묶었다.

## 0. 색은 앱 테마에서만 가져온다

- 색은 `ui/theme/Color.kt`(`DaengsColors` 와 그 별칭)와 `MaterialTheme.colorScheme` 에서만
  쓴다. **화면 파일에서 `Color(0x…)` 로 새 색을 만들지 않는다.**
- 필요한 색이 없으면 `Color.kt` 에 **이유와 함께** 더하는 PR 을 따로 연다.
- 이미 있는 예외는 이유가 적혀 있다 (예: `PlaceSearchColors.Muted` — 대비 5.10:1).
- **산책 · 장소 · 점령 화면 파일(`ui/walk` · `ui/places` · `ui/game`)에는 날것 색이 하나도
  없다.** 2026-09-12 에 들어온 화면을 훑어 여덟 파일의 날것 색(AI 검색 파란 팔레트 · 연두
  썸네일 · 회색 빈 칸 · 비슷한 날것 의미색)을 팔레트로 바꾸고 잠갔다.
  잠금 테스트: `DesignLockTest` 의 `산책 장소 점령 화면에 날것 색이 없다`.
- **Material 색 칸은 하나도 비워 두지 않는다** (`ui/theme/Theme.kt` 의 `DaengsColorScheme`).
  비운 칸은 M3 기본값(연보라 · 회보라)으로 메워져서, 그 칸을 쓰는 부품 — 고른 칩 · 카드 ·
  대화상자 · 시트 · 메뉴 — 이 크림 · 분홍 사이에서 다른 앱처럼 보인다. 2026-09-12 에
  열일곱 칸이 비어 있던 것을 채웠다. 잠금 테스트: `ThemeColorLockTest`.

## 1. 지도의 「내 위치」는 사용자 프로필이다

**SDK 기본 파란 점으로 바꾸지 않는다.**

| 적용되는 지도 | 파일 |
| --- | --- |
| 내 주변 — 검색 | `ui/places/ConnectedPlaceSearchScreen.kt` |
| 내 주변 — 찜 | `ui/places/PlaceBookmarksScreen.kt` |
| 산책 | `ui/walk/WalkScreen.kt` |

- 그리는 순서: **대표 강아지 사진 → 없으면 견종 얼굴 → 없으면 발바닥**
  (`map/provider/naver/LocationAvatar.kt`). 흰 테두리를 두른 원이다.
- **강아지 정보를 모를 때도 발바닥이다** — 불러오는 중 · 로그인 전 · 강아지 없음 ·
  통신 실패. 얼굴 리소스는 늘 `locationFaceRes(...)`(산책은 `walkFacePortraitRes`)를
  거친다. 견종 얼굴만 넘기면 두 인자가 다 null 이 되어 **그때마다 파란 점**이 된다.
- `MapHost` 를 부를 때 **`avatarRes` 와 `avatarPhoto` 를 둘 다 넘긴다.**
  **새 지도 화면을 만들 때도 마찬가지다** — 기본값이 `null` 이라 안 넘기면 조용히
  파란 점이 된다. 이번에 두 번 그렇게 됐다.
- 지난 산책을 **다시 보는** 지도(기록·일기·상세)는 「내 위치」가 아니라 이 규칙 밖이다.

**이력** — 한 번 고치면 끝이 아니었다.

| 날짜 | 무엇 |
| --- | --- |
| 2026-08-31 | `be4184e` 파란 점 → 강아지 얼굴 |
| 2026-09-08 | `344b4fd` 다시 파란 점이던 것 → 강아지 얼굴 |
| 2026-09-10 | `418e4a2` 새 검색 화면이 얼굴을 안 넘겨 **또 파란 점** (주석: "내 위치는 점") |
| 2026-09-12 | 되돌리고 **잠갔다** (이 문서 + `DesignLockTest`) |
| 2026-09-12 | 인자를 다 넘겨도 **강아지 정보가 없는 동안** 파란 점 → 발바닥 폴백을 잠갔다 |

## 2. 내 주변 카테고리 판은 막대 바로 아래에 화면 폭으로 뜬다

「식사·카페 ▾ · 카테고리」 막대를 누르면 여는 갈래 선택(`ui/places/PlacePurposeMenu.kt`).

- **막대 바로 아래(위쪽)** 에 뜬다. 화면 아래에서 올라오는 시트로 하지 않는다.
- **화면 폭**으로 뜬다 (양옆 12dp). 막대 밑 좁은 드롭다운으로 되돌리지 않는다.
- **한 줄에 세 칸**, 갈래 아홉 개가 3×3 으로 선다.
- 칸은 **최소 64dp · 아이콘 24dp · 글자 13sp.** 판은 화면 세로의 40% 를 넘지 않는다.
  **줄여도 안 되고 키워도 안 된다** — 둘 다 사용자가 실기기에서 거절했다.
- 고른 칸은 **바탕 · 테두리 · 굵기**로 말한다 (분홍 글자는 크림 위에서 2.24:1).
- 다른 창(Popup)으로 연다 — 펼쳐도 지도와 버튼의 자리를 밀지 않는다.
- 잠금 테스트: `PlacePurposeSheetLockTest` (폭 · 높이 상한 · 칸 크기 아래·위 한계 ·
  한 줄 세 칸 · 막대 바로 아래 자리).

**이력** — 2026-09-12 하루에 두 번 맞췄다.

| | 모양 | 사용자 |
| --- | --- | --- |
| 원래 | 막대 밑 드롭다운(최대 360dp) · 다섯 칸 · 칸 64dp · 아이콘 22dp · 글자 11sp | "옹졸하다" |
| 1차 | 화면 아래 시트 · 세 칸 · 칸 88dp · 아이콘 30dp · 글자 14sp | "너무 크고, 아래보다 위가 낫다" |
| **지금** | **막대 바로 아래 · 화면 폭 · 세 칸 · 칸 64dp · 아이콘 24dp · 글자 13sp** | |

## 3. 점령 · 산책 화면은 앱 테마를 따른다

- **주요 버튼(채움)은 분홍 `DaengPink` 다** — 「산책 시작」과 같다. 진한 갈색으로 채우지
  않는다. 잠금 테스트: `DesignLockTest` 의 `점령 산책의 채움 버튼은 진한 갈색이 아니다`.
- 장식 아이콘에 **의미색(초록 `Success` · 노랑 `Warning` · 빨강 `Error`)을 쓰지 않는다.**
  의미색은 상태를 말할 때만 쓴다 (예: 인증 완료 · GPS 수신). 「이번 시즌」 시계가 초록이었다.
- 칩 · 카드 · 대화상자의 바탕과 테두리는 0절의 테마 칸을 그대로 쓴다 — 화면에서 따로
  칠하지 않는다.
- **점령 규칙 창의 여백은 줄이지 않는다.** 제목 위 20dp · 좌우 24dp · 아래 버튼 둘레 20dp ·
  점수 카드 안 20dp. 전에는 제목 위 8dp · 본문 좌우 16dp · 버튼 둘레 12dp 여서 사용자가
  실기기에서 "꽉 낀다 · 글씨가 끝에 붙어 있다" 고 했다. 잠금 테스트: `TerritoryRulesSpacingLockTest`.

**이력** — 2026-09-12 실기기로 점령 게임 · 규칙 창 · 북마크 · 내 점령지 · 산책 화면을 봤다.
진한 갈색 채움 버튼 넷(`TerritoryGameScreen` 1 · `TerritoryGameRulesDialog` 3)과 초록
시계 하나를 분홍으로 바꾸고 잠갔다.

## 4. 산책은 강아지와 함께다

- **등록한 강아지가 없으면 산책을 시작할 수 없다.** 강아지가 있어도 **한 마리는 골라야**
  시작된다 (`ui/walk/WalkDogPick.kt` 의 `canStartWalk`).
- **예외 없다** — 강아지 등록 전 · 목록 불러오기 실패 · 둘러보기 모두 막는다.
- 막았으면 **왜 막았는지 한 줄로 말한다** (`walkStartBlockedReason`). 강아지가 없으면
  "먼저 강아지를 데려와 주세요".
- **"강아지가 없어도 산책할 수 있다" 는 말을 화면에 두지 않는다.**
- 잠금 테스트: `WalkDogPickTest` (규칙) · `DesignLockTest` 의 `강아지 없이 산책을 권하는 문구가 없다`.

**이력** — 2026-09-06 사용자가 "강아지와 하는 산책 앱이니 강아지 없이는 안 되게" 로 정했는데,
그때 둘러보기만 예외로 열어 두었다. 그 틈으로 목록 불러오기에 실패한 계정도 강아지 없는
산책을 시작할 수 있었고, 산책 카드에는 "등록한 강아지가 없어도 산책은 기록할 수 있어요"
가 떠 있었다. 2026-09-12 예외를 없애고 잠갔다.
