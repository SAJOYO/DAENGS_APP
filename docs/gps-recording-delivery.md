# GPS 기록 전달 · 2차 구현

설계 기준은 [#282](https://github.com/SAJOYO/DAENGS_APP/pull/282), 구현 PR은 [#283](https://github.com/SAJOYO/DAENGS_APP/pull/283)이다. 이 단계는 수신·저장·종료 경계를 바꾼다. 이동 판정 엔진과 속도 표시의 연속성 정책은 후속 단계다.

## 수신과 저장

`FusedLocationSource.subscribeRecording`은 전용 단일 실행기에서 관측을 전달한다. 화면에서 쓰는 Flow를 기록 통로로 재사용하지 않는다. 실행기 대기 용량은 콜백 64개, `WalkIngress` 대기 용량은 관측 256개다. 저장 중인 한 관측은 큐 밖에 있을 수 있다. 이 숫자는 초기 운영값이며 단말의 최대 배치량·저장 지연 측정 후 조정한다.

콜백은 원본 복사, 시각·번호 부여, 큐 제출만 한다. `offer`와 `seal`이 같은 짧은 락을 사용하므로 종료와 경합해도 접수 번호에 중복이나 역전이 생기지 않는다. 번호는 첫 큐 제출 전에 부여한다. 큐 포화 시 첫 실패 번호와 `INGRESS_OVERFLOW`를 남기고 접수를 닫는다. 실패 뒤에도 이미 받아 둔 원본은 순서대로 저장한다. 실행기 단계의 포화는 아직 관측 번호가 없으므로 `SOURCE_DELIVERY_FAILURE`로 구분한다.

애플리케이션 IO scope의 소비자는 기존 `WalkFixWriter`에 한 번에 한 관측만 제출하고 저장 완료를 기다린다. 정책·지도 계산이 늦어져도 원본 저장은 계속된다. 기존 공용 writer 큐는 다른 명령과의 순서를 위해 유지하지만 GPS 원본 대기를 그 무제한 큐에 쌓지 않는다.

`IngressProgress`에는 접수/연속 저장 번호, 저장 개수, 현재·최대 대기 개수, 수신→저장 지연, 실패 원인을 둔다. 중간 저장이 실패한 뒤 나중 번호가 저장되어도 연속 저장 번호는 실패를 건너뛰지 않는다. 화면은 저장 번호를 신호로 삼아 `observationsAfter`를 128개씩 읽는다. 화면 상태의 중간 발행이 생략되어도 원본 조회 커서가 건너뛰지 않는다. 기존 경로 계산·snapshot은 이번 단계에서 유지한다.

## 원본과 호환성

Room 15는 기존 원본 표에 nullable 필드를 추가하고 `walk_recording_epoch`를 만든다. 예전 행에 실제로 없었던 속도·시각을 만들어 넣지 않는다.

| 필드 | 의미 |
| --- | --- |
| `ingressSeq` / `clientSeq` | 한 세션에서 공유하는 접수 번호. 기존 핀 참조·서버 전송과 같은 번호를 유지 |
| `sourceEpoch` | 위치 구독마다 바뀌는 ID. 재개 시 새 ID와 chain을 사용 |
| `clockEpochId` | 서비스 실행의 단조 시계 비교 범위. 프로세스 재시작 후 이전 범위를 이어 쓰지 않음 |
| `elapsedRealtimeNanos` | 기기 측정 시각 |
| `receivedElapsedNanos`, `receivedAtMillis` | 앱 접수 시각 |
| `speedMps`, `speedAccuracyMps` | 기기 속도와 속도 정확도. 존재 여부도 nullable로 보존 |
| `bearingDegrees`, `bearingAccuracyDegrees`, `provider` | 기기 방향·정확도·공급자 원본 |
| `recordingEligible` | 이번 구독 시작 이전의 캐시 관측 또는 미래 시각인지 구분 |

기존 `clientSeq`는 Int이므로 그 한계를 넘으면 새 번호로 조용히 순환하지 않고 기록 실패로 닫는다. 원본 삽입과 epoch 저장 개수 증가는 하나의 Room 트랜잭션이다. 동일 원본 재제출은 멱등이며, 같은 번호에 다른 원본 또는 다른 세션·chain·시계 범위를 제출하면 실패한다.

시작 이전 캐시도 `fixes`와 원본 페이지 조회에서 보존한다. 서버의 finalize 계약은 `terminalClientSeq == expectedPointCount - 1`이므로 원본을 걸러 전송 번호를 재작성하지 않는다. 로컬 경로·시간·체류·행동 핀 후보에서 캐시를 제외한다. APP #305 / DEV #441은 recordingEligible의 서버 전송·저장·복원·핀 검증까지 연결한다. [앱 연결 문서](action-pin-app-integration.md)의 공통 계약을 따른다. 속도·단조 시각·epoch 전체의 서버 백업과 이동 정책 재생은 이 구분 계약에 포함되지 않는다.

APP #310은 신규 핀을 v1으로 유지하면서 위 보완 구현을 보존한다. GPS 구분 지원 서버에서는
저장 receipt를 검증한다. 미지원 서버에는 v1 전송을 계속하고 로컬 구분 원본을 유지하며,
그 서버에 구분까지 저장됐다고 주장하지 않는다. 기존 v2 기록은 원래 형식과 검증을 유지한다.

## 일시정지·종료·복구

종료 경계는 `seal` 시점에 접수한 마지막 번호다. 이미 접수한 관측을 버리는 `cancel` 대신 큐를 `close`하여 소비한다. 경계 이후 콜백은 이전 epoch에 들어가지 않는다. 아직 위치 공급자가 전달하지 않은 배치를 강제로 요청하는 flush는 이 단계의 보장 범위에 없다.

1. 접수 게이트와 활동 타이머를 닫고 위치 구독 제거를 기다린다.
2. 접수한 원본을 모두 저장하고 epoch의 경계·개수·실패 여부를 기록한다.
3. 저장 원본의 화면 커서를 따라잡고 행동 핀 처리를 마친다.
4. 일시정지는 PAUSE로 남긴다. 일시정지 상태에서 종료하면 빈 STOP epoch를 추가한다.
5. 처음 번호부터 마지막 번호까지 epoch가 연속이고 모든 개수가 일치하며 마지막이 명시적인 STOP인 경우에만 세션 종료·일기 준비 트랜잭션을 실행한다.

시작·일시정지 처리 중 받은 종료 요청도 보류했다가 실행한다. 구독 제거는 10초, 원본 drain은 30초를 기다린다. 시간 초과·포화·저장 실패는 정상 완료나 짧은 산책 삭제로 처리하지 않는다. 오류 상태에서 종료하면 활성 세션을 해제하되 DB의 미완료 원본을 유지한다. 완료 뒤 일기·전송 예약 실패는 이미 저장된 산책의 무결성 실패로 바꾸지 않는다.

앱 시작 시 현재 계정의 명시적 STOP과 완전한 drain 증거가 남은 세션만 후처리를 복구한다. 구독 중 프로세스가 종료되어 끝 경계가 없는 세션, PAUSE만 남은 세션, 실패·누락이 있는 세션은 보존한다. 이 미완료 원본의 사용자용 복구 화면은 아직 구현하지 않았다.

## 검증과 남은 범위

2026-09-11에 PR head `03b6c88`과 dev `d9c8feb`을 로컬에서 통합해 검증했다.

- `:app:assembleDebug` 통과. 실제 앱 소스와 Google 위치 라이브러리, Room KSP를 포함한다. KSP 실행 후 `15.json`은 PR에 있던 파일과 차이가 없었다.
- GPS 접수·종료, Room 저장·이관, writer·위치 전달·경로·체류·요약, 행동 핀, 산책·사진·v2 기록 동기화, 속도계의 15개 테스트 클래스를 선택해 162개를 실행했다. 처음에는 14버전 이관 테스트 1건이 실패했다. 14버전 fixture에도 기존 사진 동기화 행을 넣도록 고치고, 공개 보드와 공개 시각의 보존 검증을 보강했다. 해당 클래스 12개를 다시 실행해 모두 통과했다. 저장소 전체 테스트 실행은 아니다.
- Samsung SM-S931N / Android 16에 `.gpscheck` 별도 패키지를 설치했다. 기존 앱은 Play 서명이라 덮어쓰지 않았다. 임시 진입점은 로그인 없이 실제 `DaengsApp`, 위치 공급자, 기록 서비스, Room 및 기존 `WalkScreen`을 연결했다. 운영 계정의 로그인·동기화나 설치된 앱 데이터의 직접 업그레이드를 검증한 것은 아니다.
- 실제 GPS 기록 9건에서 `clientSeq == ingressSeq == 0..8`, mock 0건, 측정·접수 시각 보존을 확인했다. 속도는 존재한 7건, 속도 정확도는 존재한 8건에만 저장됐다. 첫 PAUSE는 5건, 재개한 STOP은 4건으로 모두 drained이며 실패가 없었다. 이 세션에서 관찰한 최대 접수→저장 지연은 약 6.1ms였다. 처리량이나 장기 지연 상한의 보장은 아니다.
- 일시정지 약 14초 동안 저장 5건과 활동 시간이 유지됐다. 재개 후 홈 화면에 있는 동안에도 저장이 늘었고 정상 종료 후 서비스가 내려갔다. 실제 산책 화면에서 수신 속도의 숫자 표시를 확인했다.
- 별도 세션을 기록 중 강제 종료한 뒤 재실행했다. 원본 2건과 종료 경계 없는 미완료 상태가 보존됐고 자동 완료되지 않았다. 시작 직후 종료, PAUSE 상태에서 바로 STOP하는 짧은 산책도 기존 완료·미완료 세션을 보존하면서 정리됐다.
- 실제 야외 장거리 보행·차량 전환, 콜백 대량 배치·기기 저장 포화, 화면 부하·배터리 측정은 남았다. 실제 GPS 확인은 책상 위 단말의 짧은 실행이며 주행 검증을 대신하지 않는다. 현재 변경으로 과거 동선 누락의 실제 원인을 확정하지 않는다.
