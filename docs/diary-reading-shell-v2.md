# 산책 열람 시안 02 — 화면 골격 (#387)

완료 산책에서 요약 카드·지도 전환·범례가 각각 세로 공간을 차지하던 배치를 정리했다.
사용자가 승인한 HTML 시안 02의 1단계이며, 장면 목록/본문의 재디자인과 시간 탐색 패널은 후속 단계다.

## 적용한 화면

- 날짜/탐색 줄, 36dp 참여견 그림과 20sp 제목, 짧은 산책 수치 행으로 상단을 구성한다.
  기본 제목 자체가 날짜인 경우 탐색 줄은 `산책 일기`로 표시해 날짜를 반복하지 않는다.
- 해당 산책의 참여견 판정과 통계 포맷은 그대로 사용한다. 다른 화면에서 쓰는 요약 카드는
  유지하고, 산책 열람 소비자에만 `compact` 표시를 적용했다.
- `보행 중심 / 전체 기록`과 관측 경로 범례를 지도 위에 나란히 배치한다.
  폭이 부족하면 겹치거나 글자를 자르는 대신 도구 줄이 감긴다.
- 범례는 실제 관측 경로가 있을 때만 나타난다. 두 역할이 함께 있으면 `관측 경로 2종`으로
  묶고, 눌렀을 때 제외/미확정의 선과 설명을 각각 보여준다. 선의 색/모양은 실제 렌더 정책을 사용한다.
- 탭의 밑줄은 선택한 글자 아래에만 두며, 오른쪽에 48dp 터치 영역의 접기/펼치기 버튼을 둔다.
  서랍 위 모서리는 24dp, 그림자는 4dp로 조정했다. 공통 간격/크기는 `DiaryReadingChrome`에 있다.
- 기존 세 높이의 계산식과 중간 높이 독립 스크롤은 유지한다. HTML의 최소 높이를 고정값으로
  복사하지 않고, 줄어든 상단 아래 실제 가용 높이에 기존 계산식을 적용한다.

## 지도 가림과 선택

지도 도구 줄의 실제 측정값을 `DiaryMapViewport`에 전달해 카메라 상단 여백과 표식 가림 판정에
반영한다. 지도 설정 버튼은 그 아래 오른쪽에 둔다. `MapVisibilityQuery.topRightCoverTopPx`는
이 버튼의 세로 위치를 나타내며, 버튼 위/아래의 노출된 표식을 가려진 것으로 처리하지 않는다.

서랍의 현재 높이는 가림 판정에만 사용한다. 표식 선택이나 접기/펼치기가 별도의 카메라 요청을
만들지 않는다. 지도와 같은 원본을 소비하는 개발용 열람 화면에도 동일한 도구/여백 연결을 적용했다.

## 검증 (2026-09-13)

- debug 빌드 성공. 관련 JVM/UI 검증 12개 클래스 52개 통과 후, 기본 날짜 제목 정리를 포함한
  최종 소비자 확인 4개 클래스 33개 통과. 중복 15개를 제외하면 13개 클래스 70개다.
- 포함 범위: 읽기 기준, 세 단계 서랍, 지도 선택/전체 보기, 장면 삭제, 시간 탐색과 보조 안내,
  상세 화면 진입, 기존 디자인/테마 잠금. 기존 잠금 테스트는 변경하지 않았다.
- 새 검증: 지도 범례의 배치와 팝업이 카메라/서랍을 유지하는지, 320dp/글꼴 1.3배에서 탭과
  서랍 조작/읽기 공간이 남는지, 아래로 옮긴 설정 버튼의 가림 영역을 정확히 판정하는지.
- `DiaryReadingStyleTest`의 native 렌더를 390dp와 320dp/글꼴 1.3배에서 확인했다.
  상단 요약, 지도 도구, 탭/모서리를 시안과 대조했다. 지도 영역은 이 렌더에서 자리 표시다.
- 기존 `com.daengs.app.locationreview` 패키지를 교체 설치하고 두 APK의 `Success`를 확인했다.
  측정 합성 기록의 구간/장면 복귀와 제한 재생을 3개 앱 프로세스에서 검증했다.
- Naver 지도와 실제 Room/편집기를 사용하는 `DiaryEditorDeviceTest` 4개 통과.
  서울 합성 기록에서 표식 선택 전후 지도 배경 위치를 화면으로 대조했고, 서랍 손잡이의
  실기기 좌표 `[0,1485][1080,1548]`가 유지되는 것도 확인했다.

화면 재현:

```powershell
./gradlew.bat :app:testDebugUnitTest --tests '*DiaryReadingStyleTest' --tests '*DiaryReadingShellUiTest' --tests '*DiaryMapNavigationTest'
./gradlew.bat -I tools/naver-map-review.init.gradle :app:assembleDebug :app:assembleDebugAndroidTest -PslimAbi=arm64-v8a
```

지도 검증용 키는 로컬 빌드 환경에만 주입한다. 실기기 패키지와 실행 절차는
[지도 검증 도구](../tools/naver-map-review/README.md), 프로세스 복원 절차는
`tools/run_measurement_device_review.py --range-context`를 따른다.
native 렌더는 `app/build/outputs/diary-reading/`, 이번 작업 환경의 실기기 캡처는
워크스페이스 `.tooling/shell-v2-device/`에 보관했다.

실기기는 합성 자료를 실제 앱의 읽기/편집 코드로 검증한 것이다. 실제 서버 로그인/업로드 검증을 뜻하지 않는다.
