# 종료한 산책을 한 번만 공개하기

APP #276 / DEV #429에서 시작했고, APP #311 / DEV #443에서 지도 우선 표시와 20초 예산으로 갱신했다.

## 사용자 흐름

산책 종료 → 저장된 동선 지도 열람 + 장면 준비 → 완성된 장면 공개 → 같은 카드에서 수정.

- 새 종료는 종료 후 20초의 초기 준비 예산을 사용한다. 상세 진입·새로고침 시 다시 세지 않는다.
- 저장된 지도·동선은 바로 표시한다. 이동·확대·전체 동선 보기가 가능하고 하단 장면 영역만 로딩한다.
- 준비 중에도 동선 탐색 탭과 방향 안내를 사용할 수 있다. 장면이 공개되어도 선택한 탐색 탭과 지도 위치를 유지한다.
- 준비 중에는 임시 카드와 편집기를 열지 않는다. 완료되면 지도 컴포넌트를 유지하면서 장면을 표시한다.
- 유효한 서버 보드가 먼저 도착하면 바로 공개한다.
- 마감까지 결과가 없으면 기기에 준비한 기본 보드를 공개한다.
- 공개 후 늦은 AI 응답은 표시 보드를 바꾸지 않는다.
- 새로고침은 저장된 상태를 다시 읽는다. 생성 요청/타이머 재시작이 아니다.

## Room 14

`walk_diary_publication`은 종료 시작 시각, 마감, 로컬 기본 보드, 공개 보드와 공개
시각을 저장한다. 세션 첫 close와 준비 행 생성을 한 트랜잭션으로 묶는다.
이미 끝난 세션과 서버에서 복원한 세션에는 준비 행을 새로 만들지 않는다.
13→14는 빈 표만 추가하며 기존 원본·분석·사진·수정본을 변경하지 않는다.
세션 삭제 시 준비/공개 행도 함께 삭제한다.

공개는 `publishedBundle IS NULL` 조건의 한 번 쓰기다. 서버 후보는 마감 전,
기본 보드는 마감 이후에만 쓸 수 있다. 서버 원본 검증과 후보 채택은 같은 DAO
트랜잭션에 있다. 본문 편집도 준비 중에는 저장 단계에서 차단한다.

## 로컬 기본 보드

별도 `walk-local-diary-board-v1` 형식이며 서버 응답인 것처럼 위장하지 않는다.
기존 지도 동선 필터를 사용하고 다음 재료로만 구성한다.

- 시작·종료: 저장된 시각의 경계 카드. 해당 시각의 실제 GPS가 없으면 위치를 비운다.
- 메모·행동·사진: 모두 보존한다. 사용자가 쓴 메모와 줄바꿈을 유지한다.
- 동선 중간 지점: 중간 장면 목표 5장에 부족한 만큼 연속 구간 안의 미충족 간격에서
  실제 관측점을 선택한다. 양쪽 기존 지점과 최소 80m의 경로상 간격을 확보한다.

시작·종료는 중간 목표에서 제외한다. GPS 공백을 직선으로 잇거나 임의 좌표를 만들지
않는다. 짧은 동선에 목표 수를 억지로 채우지 않는다. 서버의 체류/속도 판정기는
복제하지 않는다. 따라서 네트워크가 없을 때의 후보 구성은 서버 구성과 다를 수 있다.

## 실행과 재진입

종료 저장을 flush하고 유지할 산책인지 판정한 뒤 application scope에서 준비한다.
인증·전송은 별도 coroutine이며 기존 WorkManager 업로드 재시도도 유지한다.
업로드 때문에 로컬 마감 타이머가 막히지 않는다. 앱 재시작과 상세 재진입은 저장된
준비 행을 다시 읽고, 이미 마감이 지났다면 네트워크 없이 기본 보드를 확정한다.
OS가 프로세스를 중지한 동안에는 실행되지 않으며 다음 실행에서 복구한다.

기존 준비 행의 10초 마감은 연장하지 않는다. 새 Room 스키마/마이그레이션은 없다.
서버가 광고한 `budget_ms`와 로컬 남은 시간 중 작은 값만 전송하므로 10초 서버와도 호환된다.
배경 수집 때문에 `pending`을 받으면 같은 마감 안에서 2초 간격으로 상태를 확인하고
생성을 다시 요청한다. 이미 `running`이면 조회하며, 예약/마감과 `refresh=false`를 유지한다.
공개·마감 이후에는 추가 조회나 생성 요청을 시작하지 않는다.

새 서버 capability가 없으면 예산 필드를 보내거나 구형 LLM 생성으로 우회하지 않고
로컬 기본 보드를 사용한다. 공개된 세션의 이후 원본 업로드는 계속하지만 새 LLM
생성은 시작하지 않는다.

## 사용자 수정과 호환성

Reader는 공개된 보드를 우선한다. 동기화 ACK/정책 변화로 본문을 버리지 않는다.
나중에 추가·수정·삭제한 사용자 기록은 해당 카드에 반영하며 다른 장면과 편집은
보존한다. 준비/공개 표가 없는 기존 산책은 기존 Reader·생성 동작을 유지한다.
목록 제목과 검색도 공개된 보드를 기준으로 하여 늦은 AI 제목이 섞이지 않는다.

공개본과 사용자 수정본은 현재 로컬 저장 범위다. 다른 기기로 동일한 확정본을
전송하는 서버 계약을 추가하지 않았다. 실제 기기의 종료부터 공개까지 걸린 시간,
live Gemini 채택률은 별도 운영 검증 대상이며 이번 JVM 검증의 측정 결과가 아니다.

## 검증

`WalkDiaryPublicationTest`는 실제 Room에서 종료 중복 호출, 준비 중 편집 차단, 마감 전후 CAS,
후보 우선권과 사람 편집, 만료 후 복구, 기록 추가/삭제와 동선 앵커를 확인한다.
`WalkDiaryPublicationLifecycleTest`는 실제 공개 조정기·동기화·Room·Reader를 연결한다.
공개 조정기의 디스패처와 시계는 수동으로 진행하는 같은 가상 시간을 쓴다.
Room 쿼리·Reader를 기다리는 시간이 공개 마감을 자동으로 넘기지 않도록 분리한다. 서버 무응답/실패에도
마감에 공개되는지, 빠른 후보와 늦은 응답, 계정 변경, 중복 진입과 남은 시간 복구를 확인한다.
앱의 기본 실행 디스패처는 `Dispatchers.IO`다.

`WalkDiaryBoardSyncTest`는 준비 중, 만료 후 미공개, 공개 완료를 구분해 HTTP와 생성 예산을
확인한다. 공개 행이 없는 기존 산책의 호환성 사례는 별도로 유지한다.
수집 `pending` 후 재시도·남은 예산 감소·10초 서버 상한을 함께 확인한다.
`WalkDiaryMapScreenTest`는 준비 중 지도 조작, 하단 로딩, 완료 후 지도 재생성/크기 변경 방지를 검증한다.
동선 탐색 탭 왕복·공개 시 선택 유지, 진입 경로에 맞는 뒤로가기, 방향 확대와 공개 전후 편집 가능 시점도 확인한다.
제목 정책은 `WalkHistorySearchTest`가 기존 분석 제목 무효화와 공개 제목 보존을 각각 검증한다.
표적 명령은 [테스트 안내](../app/src/test/README.md#일기스토리보드기록-검색)를 따른다.
폰 설치와 실제 지도 SDK 화면, 실서버 응답 속도 검증은 별도다.

### 지도 우선 표시 실기기 확인 (APP #311)

2026-09-11, SM-S931N의 별도 검증 앱에서 합성 동선 121점·기록 3개를 사용했다.
실제 Room·업로드·Reader·지도 SDK를 연결하고 로컬 DEV API에서 확인했다.
- 25초 지연 응답: 20.002초에 기본 7장 공개, 늦은 응답 후에도 공개 해시 유지.
- 실제 Gemini: 수집 `pending` 뒤 재요청, 4.218초에 서버 7장 공개. 준비 중 지도 이동이 완료 후 유지됨.
- 전체 화면 로딩 대신 하단 장면 로딩, 지도·동선·출발/도착·지도 타일 표시를 확인함.
- 입력/출력 상한과 공개 회귀 35개 및 UI 15개, 서버 공개 API 9개 통과. 설치 APK 해시 일치.

공간자료 worker는 로컬에서 0.5초 주기로 실행했고 시설 조회는 빈 결과로 대체했다.
공원 배경이 있는 기록 1장의 AI 서술과 나머지 기본/사용자 문장이 함께 공개됐다.
이 단일 합성 사례의 시간은 운영의 지연 분포나 채택률을 뜻하지 않는다.
