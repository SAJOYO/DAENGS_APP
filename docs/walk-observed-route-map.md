# 보조 관측 경로와 장면의 지도 표현

2026-09-12 · APP #342 · 완료 산책 화면의 3번 작업

보행선 밖에 핀만 남던 장면을 해당 관측 경로와 함께 읽는다. 완료 legacy 기록의 확인 가능한
보조 경로를 이중선으로 표시하고, 장면이나 관측 경로 버튼을 선택하면 같은 종류의 선을
강조한다. 보행 제외/미확정은 안내 문구로도 구별한다. 기존 거리·보행선·장면 본문은 보존한다.

## 판정과 표시 채택

[#338의 관측 연결 후보](walk-observation-connectivity-review.md)는 진단 기본값을 유지한다.
화면은 `ObservedRouteDisplayPolicy`, 버전 `legacy-observed-display-v1`을 별도로 사용한다.
연결 평가기의 버전·전체 매개변수와 표시 정책 버전을 함께 보고한다.

표시용 연결 매개변수는 #338 기본값 중 속도 벡터 변화 계수를 **4m/s²**로 제한한다.
나머지는 정확도 25m, 인접 간격 500ms~10초, adjusted speed 35m/s, 최소 3개 연속 구간,
시각 근거 차이 1초다. 민감도가 확인된 경계를 그대로 채택하지 않으려는 보수적 선택이다.
특정 장면을 붙이기 위한 기준 완화나 새로운 보행 정책이 아니다.

그 결과 A는 진단 기본 후보 339→362 중 **340→362**만 표시한다. 339→340은 보류하며
양 끝을 임의로 잇지 않는다. 보행 끝과 보조 경로 시작 사이의 설명/공백 선택은 다음 단계다.
B는 기존 보행 소유 범위만 있으므로 보조선을 추가하지 않는다.

입력의 기존 보행 소유자, 단절·시간 오류, source/clock epoch, 원본 순번·위치 품질을 모두
따른다. motion 기록, 미완료 기록, 읽기 근거가 없는 기록은 새 표시 정책을 적용하지 않는다.
LIVE 산책과 여러 산책을 모아 보는 지도에도 이 계층을 자동 적용하지 않는다.

## 원본에서 장면까지

`ObservedRouteReview`는 같은 읽기에 속한 원본 구간과 방향 근거를 준비한다.
`CompletedRouteReview.sceneFocus`는 기존 보행 대응을 유지하고, 제품과 검토 앱은
`recordSceneFocus`에서 보행 대응을 먼저 사용한 뒤 보조 관측 대응을 구한다.

장면의 원본 관측 주소가 있으면 session·seq·chain·시각·좌표를 검증한다. 시간만 가진
사진/메모는 유일한 시간 범위를 먼저 찾고, 그 안에서 위치를 확인한다. 공백·다른 방문·
겹친 시각을 공간 최근접으로 대신 고르지 않는다. provisional/legacy 위치 근거는 거부한다.

임의로 장면 시각을 바꾸면 원본 관측을 그대로 빌릴 수 없다. 명시적인 start/end 제어 사건만
첫/마지막 원본 관측을 전후 위치 문맥으로 참조할 수 있다. A 장면 6은 종료보다 **1407ms
이전**의 확인 위치로 남기고 시각을 안내한다. 관측 시각을 기록 종료로 덮어쓰지 않는다.

강조 범위는 같은 관측 구간 안에서 해당 시점 주변 10초·약 40m로 제한한다. 경계 바로
옆의 온전한 첫 edge는 포함할 수 있으므로 40m는 기하를 잘라내는 상한이 아니다.
원본 핀은 이동시키지 않는다. `SceneRouteFocus.observedParts`는 표시 시점의 범위이며
장면 자체의 영구 소속이나 새 측정 ID가 아니다.

## 방향 근거

위치 연속성만으로 이동 화살표를 허용하지 않는다. 원본 edge의 변위가 3m보다 크고 다음 중
하나를 만족해야 한다. 보고 정확도 반경은 통계적 오차 상한으로 해석하지 않는다.

1. edge 변위가 양 끝 보고 반경 합 + 3m보다 크다.
2. 그렇지 않으면 같은 확인 구간의 앞뒤 최대 2개 관측을 더 사용한다(최대 5개 edge,
   10초 이내). 문맥 양 끝 변위가 반경 합 + 3m보다 크고 원본 edge 방향이 문맥 방향과
   60도 이내로 일치해야 한다.

두 번째 규칙은 샘플 간 이동이 보고 반경보다 짧아도 연속 이동의 방향을 검토할 수 있게 한다.
각 화살표에 실제 edge 주소와 방향 근거 범위를 남긴다. 문맥 양 끝을 잇는 직선은 그리지
않고 원본 edge의 방향을 사용한다. 정지 흔들림·공백을 방향으로 바꾸지 않는다.

화면 배치는 기존 충돌 회피를 재사용한다. 일반 간격 23dp 양쪽이 핀에 막히면 48dp를 추가로
시도한다. 다른 경로에 더 가까워지는 위치나 화면/마커/선과 충돌하는 위치는 거부한다.
이 때문에 방향 근거가 있어도 화면 공간이 없으면 화살표가 표시되지 않을 수 있다.

## 표시와 선택

`RouteRenderPart`는 역할·선택 상태·원본 기반 ID·방향 edge를 전달한다.
`RecordPresentationPolicy` (`record-route-style-v1`)가 기본과 선택의 색/폭/가운데 색을
함께 결정한다. Naver renderer에서 보행 판정을 다시 하지 않는다.

| 이동 | 기본 | 선택 | 설명 |
|---|---|---|---|
| 기존 보행 | 기존 분홍 계열 경로 | 기존 강조선 | 기존 의미 유지 |
| 보행 제외 관측 | 청록 이중선 | 더 진하고 굵은 이중선 | 보행거리 합계 제외 |
| 보행 미확정 관측 | 황갈색 이중선 | 더 진하고 굵은 이중선 | 보행 여부 미확정 |

보조선은 색뿐 아니라 가운데가 구분된 선과 범례/문구로 보행 실선과 구별된다.
Naver [PathOverlay](https://navermaps.github.io/android-map-sdk/reference/com/naver/maps/map/overlay/PathOverlay.html)의
색·폭·테두리를 사용한다. 원본 좌표를 곡선으로 바꾸거나 별도 래스터 에셋을 추가하지 않는다.

공유 `WalkRouteSelection`에 Auxiliary를 추가했다. 관측 경로 버튼은 해당 범위로 확대하고,
장면 선택은 원래 핀으로 이동하며 해당 방문 주변을 강조한다. 장면·보행 구간·관측 구간·
통과·재생은 한 번에 하나만 선택한다. 새 읽기를 준비하면 보조 구간 선택은 초기화한다.
`recordPresentationLayer`는 현재 준비된 detail과 같은 객체의 결과만 사용한다.

최초 카메라는 기존 보행 범위를 유지한다. 보조 데이터는 계속 지도에 있지만 화면 밖일 수
있다. 현재는 장면/관측 구간 선택으로 접근한다. 전체 기록 카메라와 화면 밖 장면 개수는
5번 작업이다. 보조 경로를 재생 시간이나 보행거리 합계에 추가하지 않는다.

## 검증 방법

검토 앱의 실제 A/B 조회는 기존 보고서 필드를 보존하면서 `record_presentation`을 추가한다.
여기에 표시/스타일/연결 정책, source seq, 방향 근거 범위, 실제 장면 대응이 들어 있다.
`PrivateObservedRouteMapReplayTest`가 #338의 같은 원본·장면 해시로 이를 재생한다.

검토 앱의 **가상 반례 지도 확인**은 왕복·공백 핀·제외 이동·작은 흔들림을 메모리에서만 만든다.
계정 기록을 수정하거나 업로드하지 않는다. 실제 기록의 검증과 합성 반례 검증을 구별한다.
작은 흔들림은 보행 미확정 문구를 유지하고 화살표는 없다. 공백 핀은 앞뒤 선을 만들지 않는다.

관련 검증은 `ObservedRouteReviewTest`, `ObservedRoutePresentationTest`,
`ObservedRouteMapFixtureTest`, `PrivateObservedRouteMapReplayTest` 및 #338의 회귀 테스트,
기존 지도·구간 선택·화살표 배치 테스트로 수행한다. 원본 거리·활동시간·보행선·보행 장면
대응 보존, 다른 방문·공백 재연결 방지, 원본 주소/수정 시각/오래된 읽기, 선택 스타일,
정지 무방향, 전체/선택 상태 전환을 확인한다. 실제 명령과 실행 결과는 PR 본문에 기록한다.

실제 좌표·계정·장면 본문·기기 캡처는 개인 폴더에만 둔다. 독립 리뷰 승인·머지·출시 앱
배포는 검토 앱에서의 확인과 다른 상태다.

자체 코드 검토와 실기기 자료 준비까지 수행했다. 보조선 직접 탭의 통과 검사 확장은 이번에
포함하지 않으며, 보조 구간 선택은 관측 경로 버튼과 장면 카드/핀에서 시작한다.

## 남아 있는 경계

연결/방향 정책은 보수적인 표시 휴리스틱이다. 부드러운 GPS 드리프트와 실제 급회전의
실세계 분류 정확성을 검증 완료로 선언하지 않는다. 실제 A/B에는 다중 보행 구간이 없어
그 반례는 합성 기록으로 확인한다. B 원래 270m와 확보 원본 271.531737m 차이도 별도다.

공백·전환·시작/종료 전체 UX는 4번, 전체 기록 접근/비동기 갱신은 5번이다. 옛 자동 본문의
736m/951m를 현재 보행거리로 치환하지 않는다. 거리 정의와 측정 버전의 본문 연계,
완전한 motion 기록의 API→APP 전환도 이번 표시 작업과 분리해 유지한다.
