# 산책 흔적 브러시 시연

산책 기록 탐색 화면이 공유하는 표시 계약이다. 한 산책을 한 장으로 칠한다. `전체 흔적`은 단색의 겹침으로, `겹친 구간`은 겹친 산책 수에 따른 색으로 표시하고 해당 구간의 관련 산책을 조회한다. 일반 사용자 화면의 진입점은 아직 연결하지 않는다.

## 표시 계약

- 입력은 산책 ID와 `hex-v1`의 양수 지지 영역 셀 집합이다. 동일 산책의 중복 셀은 한 번만 칠한다.
- `occupancy`·`peak`·행동 개수·재통과 횟수는 불투명도에 사용하지 않는다. 저장된 공간 데이터나 기존 `walk_utilization` 평균 지도 계약을 변경하지 않는다.
- 한 장의 기본 알파는 고정값 **0.14**, 최종 픽셀 알파의 상한은 **0.40**이다. 완전히 덮인 부분은 `min(0.40, 1 - (1 - 0.14)^k)`이며 두 장은 0.2604다. 전체 산책 수나 조회 최대값으로 재정규화하지 않는다.
- 가장자리는 부드럽게 처리한다. 표시 마스크는 저장 셀의 연속적인 표현이며, 실제 GPS 중심선이나 시설 진입의 증거가 아니다.
- 지도에서 숨긴 산책은 표시 합성에서 제외하고 복원할 때 같은 마스크를 사용한다. 숨김은 원본 셀의 산책 귀속이나 전체 조회의 겹침 근거를 바꾸지 않는다.
- 서로 먼 영역은 세계 좌표에 고정된 별도 타일로 만든다. 빈 공간을 포함한 거대한 단일 비트맵을 만들지 않는다.

## 계산과 지도 연결

`TraceBrush`는 Android에 의존하지 않는 표시 전용 계산이다. Web Mercator의 고정 래스터 위에 셀의 합집합을 만들고 안쪽 축소·Gaussian·smoothstep을 적용한다. 원래 육각형 외곽으로 다시 자르지 않는다. 서로 떨어진 성분은 독립적으로 처리하며, 작은 성분이 전부 사라질 때는 약한 축소 조건으로 다시 만든다.

기본값은 픽셀 간격 2u, 타일 128×128, 안쪽 축소 2u, Gaussian sigma 5u, smoothstep 0.12~0.5다. `u`는 위도에 따라 실제 거리와 달라지는 Web Mercator 단위다. GEO `c8d0cb1`의 `2026-09-07-walk-overlap-thin-brush.md` 명세를 참고했으며, 밀도에 따라 알파를 바꾸는 실험 정책은 가져오지 않았다.

초기 시연에서 smoothstep 상한 0.9는 한 셀 폭의 중심을 지나치게 옅게 만들었다. Gaussian과 하한 0.12는 유지하고 상한을 0.5로 낮춘 현재 형상 정책을 사용한다. 가장자리가 차지하는 비율이 큰 작은 흔적은 넓은 면 중앙보다 옅게 보일 수 있다. 기본 알파 0.14와 최종 상한 0.40은 형상과 별도의 현재 합성 정책이다.

한 산책은 최대 5,000셀·256타일, 성분별 계산은 합계 512타일까지 제한한다. 합성은 최대 400산책·입력 1,024타일·출력 256타일이다. 제한을 넘으면 일부를 조용히 누락하지 않고 실패를 반환한다. 대량 산책의 캐시·뷰포트별 부하 조절은 실데이터 연결 단계에서 별도로 측정한다.

출력은 북쪽부터 시작하는 행을 가진 `TraceRasterTile`이다. 선택적인 픽셀별 RGB가 없으면 기존 단색을 사용한다. `NaverWalkTraceLayer`는 합성된 알파와 표시 색을 한 비트맵에 기록하고 실제 Naver `GroundOverlay`에 올린다. 색별 오버레이를 중복 합성하지 않는다. 지도 이동·확대는 원본 마스크나 기본 알파를 변경하지 않는다. 계산과 비트맵 준비는 화면 스레드 밖에서 수행하며, 레이어 교체·화면 이탈 시 기존 오버레이를 분리한다.

표시 마스크를 실제 방문 횟수·행동 확률 등의 통계 계산에 되먹이지 않는다. 겹친 구간의 근거도 아래 원본 셀 색인에서 읽는다.

## 겹친 구간 표시와 원본 근거

`전체 흔적`은 표시 가능한 산책을 합성한다. `겹친 구간`은 전체 조회에 속한 **같은 반지름의 원본 셀 → 서로 다른 산책 ID 집합**에서 최소 2·3·5회를 만족하는 셀을 고른다. 한 산책이 같은 셀을 여러 번 칠해도 한 번만 센다. 이 중 **해당 셀의 원본 참여 산책이 하나라도 표시 중인 셀**로 부드러운 표시 마스크를 만든다. 겹침에 참여하면서 숨기지 않은 산책의 합성 결과에 이 마스크를 곱하여 표시 범위를 제한한다. 참여 산책을 모두 숨긴 셀에 주변 브러시가 번져 남는 것을 막으며, 현재 페이지나 숨김 집합으로 최소 횟수와 전체 근거 ID를 다시 계산하지 않는다.

표시 마스크 캐시는 최소 횟수와 해당 기준에 영향을 주는 숨김 ID 집합을 키로 사용한다. 최대 6상태·합계 256타일만 보관하며 산책별 마스크는 그대로 재사용한다.

### 겹친 산책 수별 색

원본 셀의 서로 다른 산책 수가 색의 기준이다. 같은 산책의 재통과·체류·행동 기록 수는
이 값을 늘리지 않는다. 조회 최대값에 맞춰 색 단계를 바꾸지 않으며 최소 2·3·5회 필터도
같은 색 기준을 공유한다.

| 겹친 산책 수 | 색 |
| --- | --- |
| 2회 | 청록 `#008F9C` |
| 3–4회 | 노랑 `#E4B000` |
| 5회 이상 | 주황 `#EB6A20` |

부드러운 색 경계는 원본 셀의 분류색을 보간한 표시다. 정확한 횟수·근거는 해당 구간을
눌러 원본 색인에서 확인한다. 색을 역산하여 횟수를 계산하지 않는다. 색 처리 자체가
표시 영역·불투명도·빈 공간을 바꾸지는 않으며 알파 상한 0.40도 유지한다.

색의 입력은 전체 조회로 고정한다. 한 산책을 숨기면 해당 잉크는 줄어들지만 남은 픽셀의
색 기준과 구간의 전체 근거는 유지된다. 전체 흔적과 행동 탐색의 산책 흔적은 현재 단색을 유지한다.
범례는 겹친 구간에만 표시한다.

색 채널과 셀 지지를 같은 Gaussian으로 보간한 뒤 지지로 나누어 빈 공간 옆의 검은 테두리를
막는다. 현재 표시할 타일만 계산하고, 세계 타일 좌표·크기·픽셀 간격으로 색을 재사용한다.
색 캐시는 최대 256타일(기본 128×128 RGB에서 16MiB)이며 숨김·최소 횟수별로 복제하지 않는다.
화면에 반환하는 배열은 복사하여 캐시를 외부에서 바꿀 수 없게 한다.

겹침 색인은 최대 100,000개 셀 귀속·25,000개 원본 셀·5,000개 겹침 셀을 처리한다. 반지름이 섞이거나 겹침 처리 상한을 넘으면 **겹친 구간만 사용 불가**로 알리고 전체 흔적은 계속 사용할 수 있다. 겹침 전용 표시 마스크의 계산 실패도 같은 경계에서 처리한다.

겹침 모드에서 누른 위치는 원본 기준을 충족하고 표시 중인 산책이 하나 이상 있는 셀에 연결한다. 셀 밖에서는 셀 영역까지 **최대 12 Web Mercator u**까지만 가까운 셀을 찾는다. 이는 위도에 따라 실제 지상 거리와 다른 단위다. 응답은 선택한 **한 원본 셀**의 중심과 전체 산책 ID 집합이며, 주변 여러 셀의 ID를 합치지 않는다. 숨김은 새 위치 선택 가능 여부에만 관여하고, 선택 셀의 근거 목록에는 숨긴 산책도 남는다.

부드럽게 칠해진 흔적이나 이 색인은 시설에 실제로 진입했다는 증거도, 행동을 했을 확률도 아니다. 앱 조작과 상태 정책은 [산책 기록 탐색](walk-records-exploration.md)을 따른다.

## 로컬 실행

기존 앱 개발 환경을 사용한다. 지도 Client ID는 저장소에 넣지 않고 `local.properties`의 `daengs.naverMapClientId` 또는 `DAENGS_NAVER_NCP_KEY_ID` 환경 변수로 제공한다.

```powershell
.\gradlew.bat :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.daengs.app/.ui.walk.WalkTraceBrushLabActivity
```

샘플임을 명시한 debug 화면이며 로그인·서버·사용자 DB에 의존하지 않는다. 지도 SDK 인증이 실패해서 배경이 비어 있으면 실제 지도 시연의 완료로 보지 않는다.

## 검증 범위

단위 테스트는 산책 중복 거부, 같은 산책의 합집합, 서로 다른 산책의 고정 알파 합성, 숨김·복원, 떨어진 영역과 작은 흔적, 타일 경계의 연속성, 입력 제한을 확인한다. 실제 지도에서는 한 장/두 장 전환, 좁은 흔적과 떨어진 흔적, 숨김·복원, 줌·이동의 정렬을 확인한다.

색 추가 전 알파 상한·겹침 기준·원본 셀 선택의 대상 테스트는 고유 25개가 통과했다. `records-overlap-253` APK에서 최소 2·3·5회의 표시 영역 차이, 구간별 10회·2회 근거 조회, 숨김 뒤 근거 유지와 목록 복귀를 확인했다. 색 표현의 검증은 이 이전 결과와 구분하여 [산책 기록 탐색](walk-records-exploration.md)에 기록한다. 행동 탐색 시연은 PR #259에서 연결했으며 실제 서버·Room 연결은 후속 작업이다.
