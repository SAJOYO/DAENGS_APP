# 정상 생략 관측의 장면 연결 — APP #336

장면의 원본 관측이 기존 3m 최소 거리 규칙으로 생략돼도, 그 관측을 포함하는 수용
연결과 처리 근거가 확인되면 기존 보행선을 강조한다. 원래 장면 핀은 이동하지 않는다.
실선에 장면을 억지로 맞추기 위해 최소 거리·속도·거리 집계 정책을 변경하지 않는다.

## 한 번의 계산에서 근거까지

`TrailRecorder.onDecision`은 실제 수용/최소 거리/저정확도/고속 제외 분기에서 호출된다.
표본과 직전 수용점은 객체 정체성으로 전달한다. 같은 시각·좌표가 반복돼도 다른 원본을
빌리지 않는다. 콜백은 선택 사항이며 스냅샷을 추가 발행하지 않는다. `addAll`도 유지한다.

완료 상세의 `readCompletedRoute`는 저장된 정책을 한 번 재생해 summary·route·원본·
`LegacyRouteEvidence`를 함께 만든다. 목록·합계와 산책 중 recorder는 이 인덱스를 보관하지
않는다. 실제 Room의 `WalkHistory.sessionDetail`과 별도 검토 앱이 같은 읽기 경로를 쓴다.
motion 측정은 기존 reader를 유지하고 legacy 근거를 생성하지 않는다. 검토 앱만 명시적으로
historical 비교를 요청하며, 정책이 없는 과거 입력을 새 motion 결과로 표시하지 않는다.

근거의 read basis는 reader 버전, 정확한 summary 인스턴스, 원본 전체 값, 함께 생성된
route다. 원본·route·summary가 바뀐 detail은 과거 근거를 사용할 수 없다. 영속 ID나 서버
measurement ID가 아니며 화면의 메모리 수명 안에서만 쓴다. 계정 변경 중 상세 읽기는 거절한다.

## 연결 허용 조건

장면의 session·사건 시각·위치 근거 검증 이후 다음을 확인한다.

1. 장면의 원본 `clientSeq`가 유일하며 실제 판정이 `BELOW_MIN_DISTANCE`다.
2. 직전/다음 수용점이 현재 경로의 같은 segment에서 인접한다. 다음 수용점이 없으면
   위치만 남기며 보행 연결이나 방향을 만들지 않는다.
3. 두 수용점 사이 모든 원본은 같은 직전 수용점을 기준으로 최소 거리 생략 판정을 받았다.
   저정확도·고속 제외·mock·기록 비대상·잘못된 좌표/정확도·누락/중복 순번이 없어야 한다.
4. 원본 이웃의 chain·source epoch·clock epoch가 같고 벽시계 간격은 1–15초다.
   단조 시각이 있으면 양쪽 모두 존재하며 증가해야 한다. 시간 역전·중복·epoch 변화는
   건너뛰지 않는다. 15초는 기존 장면 대응의 보수적 시간 범위이며 새 보행 정책이 아니다.
5. 강조 확장도 위 근거가 있는 이웃 연결에서만 가능하다. legacy 경로가 고속 제외 뒤
   연결한 선을 유지하더라도, 복구한 장면이 그 선까지 강조 범위를 확장하지 않는다.

수용 연결의 원본 범위는 서로 중복 없이 한 번씩 확인한다. 원본 정렬 이후 인덱스 구성은
선형이며, 장면마다 GPS를 재판정하거나 전체 원본을 재생하지 않는다.

`SceneRouteBinding`은 사건 시각·위치 관측 시각·원본 seq·reader 버전·지원하는 연결의
양 끝 seq를 따로 전달한다. 지금은 사건 시각과 위치 시각이 일치하는 기존 조건을 유지한다.
시작/종료 사건의 다른 위치 시각을 보여주는 UX는 후속 범위다.

## 실제 기록에서 확인한 경계

A 4번의 두 수용점은 47,663ms 떨어져 있다. 그 사이에 28개 최소 거리 생략 관측이
있으므로 표시 점의 간격만 보고 GPS 공백으로 처리하면 장면이 계속 누락된다.
이 경우는 원본 관측 간격으로 확인한다. 긴 시간 동안 원본이 없는 사례와 별도로 검증한다.

| 기록·장면 | 원본 seq | 실제 판정 | 지원하는 수용 연결 |
|---|---:|---|---|
| A 2 | 110 | 최소 거리 생략 | 109 → 111 |
| A 3 | 193 | 최소 거리 생략 | 191 → 194 |
| A 4 | 294 | 최소 거리 생략 | 279 → 308 |
| B 3 | 85 | 최소 거리 생략 | 84 → 87 |

2026-09-12, 관련 9개 클래스 **87개 테스트 통과, 실패·오류·skip 0** 및
`assembleDebug` 통과를 확인했다. 개인 캡처 재생도 실행한 수치이며 전체 앱 테스트 결과는 아니다.

- A 2·3·4 / B 3: `NO_ROUTE → CONNECTED`. 원래 핀 보존.
- A 5·6: `NO_ROUTE` 유지. B 2·4: 기존 연결·강조 경로 유지.
- A: 509.49839648269614m / 390998ms, B: 271.5317371099618m / 164139ms.
  모든 원본별 판정·거리 기여 및 전체 route 값이 기존 결과와 정확히 같다.
- 출력 유무·순차/묶음 처리·chain 경계를 포함한 recorder 결과도 동일하다.
- SM-S931N의 별도 `com.daengs.app.walkreview`에 `walk-review-336` 설치 `Success`와
  설치 버전을 확인했다. 현재 기기가 잠겨 있어 장면을 누르는 실기기 화면 검증은 대기 중이다.
  정식 앱 설치나 데이터를 변경하지 않았다.

## 재현 방법과 범위

합성 회귀 `LegacySceneBindingTest`, 기존 recorder/summary/장면/탐색 테스트,
실제 Room의 `WalkHistoryTest`를 실행한다. `PrivateSceneBindingReplayTest`는
`DAENGS_REVIEW_REPLAY_ROOT`가 지정됐을 때만 저장소 밖 #335 캡처를 재생한다.
일반 환경에서는 이 개인 원본 테스트만 skip한다. 원본 좌표·계정·장면 본문은 Git에 넣지 않는다.

개인 재생은 저장된 원본·장면 SHA-256부터 확인한다. 기존 무출력 reader와 근거 출력 reader의
summary 및 전체 route 값을 비교하고, #335의 모든 원본별 처리 사유·거리 기여·총거리·
활동시간을 정확히 대조한다. 최소 거리 생략 장면만 연결을 복구하며 기존 연결의 강조 경로도
그대로인지 확인한다. 별도 진단 앱의 보고서에는 지원 연결 양 끝 seq와 두 시각을 추가한다.

이 PR은 기존 보행선과 정상 생략 장면의 대응까지만 다룬다. 보행 제외 관측의 보조선,
공백 안내, 전체 기록 카메라, 시작/종료 UX, 서버 측정 채택은 이후 단계다.
B의 원래 표시 270m와 확보 입력 271.531737m의 차이는 해결로 처리하지 않는다.
