# 전체 기록과 화면 밖 장면 읽기

APP #353 · 완료 산책 지도/장면 개선의 5번째 구현 단위.
앞 단계 #336·#338·#342·#343의 보행/보조 경로·공백·장면 대응을 같은 화면에서 탐색한다.

## 화면 계약

- `보행 중심`은 모든 보행 구간을 포함한다. 멀리 떨어져 다시 시작한 유효 보행도 포함한다.
- `전체 기록`은 보행선, 확인된 보조 경로, 위치가 있는 사건과 장면을 포함한다.
  실제 표시 위치가 하나도 없을 때만 기존 summary anchor를 사용한다.
- 두 보기는 카메라 명령이다. 어느 보기에서도 경로/장면 데이터를 끄거나 보행 집계를 바꾸지 않는다.
- 최초 진입은 보행 중심이고, 사용자가 지도를 움직인 뒤 데이터가 갱신돼도 자동으로 다시 맞추지 않는다.
- 지도 표식 선택은 카메라와 패널 높이를 유지한다. 목록 선택/명시적 보기 전환만 카메라를 이동한다.
- 보기 버튼은 지도 바깥에 두어 번호 표식을 가리지 않는다. 공백은 기존 회색 `–`이며 장면 번호를 차지하지 않는다.
- 장면 제목 아래 기존 시각 하나를 유지한다. 추가 기록/관측 시간이나 앞뒤 장면 버튼을 넣지 않는다.

`화면 밖 장면 N개` 메뉴는 가려진 장면의 번호와 제목을 보여 주고, 선택하면 일반 목록 선택과
같은 경로로 이동한다. 위치가 없는 장면은 기존 시간순 목록에서 읽으며 화면 밖 개수에 넣지 않는다.
같은 핀을 공유하는 여러 장면은 각각의 장면 ID로 세고, 중복 ID는 한 번만 센다.

## 실제 보이는 영역

`NaverMapVisibility`는 SDK projection을 읽어 회전/기울기를 포함한 화면 좌표를 얻는다.
지도 크기, 실제 bottom sheet 위치, 지도 설정 버튼이 가리는 영역을 반영한다.
번호 핀의 크기는 `DiaryPinArt.diaryPinSize`와 공유한다. 여러 번호가 합쳐진 넓은 핀도 일부가
보이면 화면 안에 있는 것으로 본다. 별도 visibility용 비트맵은 만들지 않는다.

카메라 배치용 고정 padding과 현재 패널의 가림 영역은 별개다. 패널을 끌면 가시성만 재계산하고
카메라 명령은 바꾸지 않는다. 이동 중이거나 projection이 준비되지 않았으면 개수를 확정하지 않는다.
조회에는 읽기 revision·장면 위치·가림 영역이 들어가며, 이전 조회의 콜백은 현재 화면에 반영하지 않는다.

## 경로와 장면의 함께 갱신

`WalkDiaryReadView`는 준비된 원본 detail·review·탐색 index와 그 원본에 대응하는 장면/binding을 묶는다.
이는 현재 APP reader의 화면 단위 계약이며 서버의 불변 MeasurementSnapshot 저장 기능은 아니다.

1. 새 원본을 읽고 review/index를 백그라운드에서 준비하는 동안 기존 정상 화면을 유지한다.
2. 준비된 경로를 채택할 때 경로·경계·인덱스를 한 Compose snapshot에서 바꾼다. 장면은 pending일 수 있다.
3. 장면과 원본 entry를 같은 reader emission에서 받고 해당 경로로 binding을 계산한다.
4. 최신 장면 revision과 계정 generation이 맞는 결과만 채택한다. 같은 소유자의 재로그인도 다른 generation이다.
5. 같은 원본이 다시 통지되면 기존 준비 결과 전체를 재사용해 장면과 선택이 불필요하게 사라지지 않는다.

선택한 장면의 새 대응을 기다릴 때도 읽던 패널 높이와 선택 ID를 유지한다. 새 장면 목록이 준비된 뒤
실제로 삭제된 선택만 해제한다. 장면 읽기 실패는 이미 준비된 경로를 남기지만, 원본이 사라졌다는
통지를 받은 뒤 오류가 발생한 경우에는 이전 기록을 복원하지 않는다.

화면의 `key(sessionId, accountScope)`와 채택 직전 검증으로 이전 계정의 화면 상태와 응답을 분리한다.
기존 서버 장면 저장의 board generation/entry stamp 검사는 그대로 사용한다.

## 최종 화면 리뷰 동선

1. 처음에는 보행이 읽히는 배율인지, 먼 유효 보행도 전체 보행 범위에 남는지 확인한다.
2. `전체 기록`에서 먼 장면과 확인된 보조 경로를 찾고 해당 장면을 읽는다.
3. 지도를 이동하거나 패널을 끌어 가려진 장면 메뉴를 열고, 선택한 번호와 실제 핀이 일치하는지 확인한다.
4. 보이는 회색 공백 표식과 인접 장면을 번갈아 눌러 카메라/패널이 유지되는지 확인한다.
5. 새 장면이 들어와도 읽던 위치가 유지되고, 보행 중심으로 직접 돌아갈 수 있는지 확인한다.

서버 측정 후보 API의 제품 연결, 불변 저장/manifest/chunk, 신규 보행 정책 전환은 이 PR 범위에 없다.

## 탭만 남기는 서랍 — APP #360

장면/동선 탐색 탭이 있는 완료 산책 화면은 접으면 손잡이와 두 탭만 남긴다.
처음에는 기존 중간 높이에서 장면과 지도를 함께 보여 준다. 위로 올리면 상세를 넓게 보고,
중간 높이에서 아래로 더 내리면 탭만 남는다. 세 높이를 각각 실제 드래그 정착점으로 둔다.
접힌 상태에서 탭을 누르면 중간 높이로 돌아오며, 중간/펼침에서 탭이나 장면을 바꿔도 높이는 유지한다.
접힘 높이는 손잡이와 실제 탭 높이로 정해 큰 글씨에서도 상세 내용이 아래로 새어 나오지 않는다.
탭이 없는 기존 장면 전용 화면의 접힘 방식은 유지한다.

- 손잡이 버튼은 기존처럼 중간/펼침을 전환하고, 접힘에서 누르면 중간 높이로 돌아온다.
  위아래 드래그로 세 높이를 오갈 수 있고, 뒤로 가기는 한 단계씩 낮춘다.
- 장면 목록·본문·탐색 내용은 중간 높이에서도 직접 스크롤한다. 내용 스크롤을 펼침으로 가로채지 않는다.
  실제 보이는 높이를 스크롤 영역으로 사용하여 끝부분까지 읽을 수 있다.
- 높이만 바꿀 때 장면/공백 선택과 배속 재생을 유지한다.
- 현재 탭을 다시 누르면 접힘에서만 중간 높이로 돌아온다. 다른 탭은 기존 선택 전환을 사용한다.
- 장면 상세의 `‹ 장면 목록`은 선택을 닫는 별도 동작이며 사용자가 둔 높이로 목록을 보여 준다.
- 중간 높이에서도 본문이 먼저 보이도록 경로 대응 안내는 장면 본문 뒤에 둔다.
  장면 상세의 목록 버튼·장면 번호·화면 밖 메뉴는 한 줄에 두어 본문 공간을 확보한다.
- 지도 표식 선택, 장면의 지연 갱신, 대응 계산 중에는 사용자가 둔 높이를 유지한다.
- 상세 영역을 제거하지 않고 지도 영역 아래로 가린다. 접었다 펴도 읽던 스크롤과 탐색 상태를 유지한다.
- 접힘/펼침은 실제 가림 영역만 바꾼다. 지도 크기·고정 카메라 padding·카메라 명령은 유지한다.

`WalkDiaryCompactDrawerTest`는 작은 화면/큰 글씨, 드래그와 뒤로 가기, 늦은 장면 대응,
지도 공백/장면 선택, 중간 높이에서 목록/본문 끝까지 스크롤, 손잡이 버튼,
접힌 상태의 16배속 진행 및 현재 탭 재열기를 검증한다.
기존 지도/읽기/탐색 UI와 카메라·장면 갱신·방향·디자인 잠금 회귀도 함께 실행한다.
테스트의 재생 시간은 직접 진행시키며 실제 ticker와 SDK 지도 동작은 검토 앱에서 별도로 확인한다.
