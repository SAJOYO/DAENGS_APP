# GPS 속도 표시 — 4차 (#306)

상태: 표시 전용 reducer·세션 소유 객체·Compose 미리보기. **현재 산책 서비스와 기존 속도계에는 아직 연결하지 않는다.**

## 범위와 소유권

`MotionDisplaySession`은 한 산책 세션의 실행층이 만들고 직렬 호출한다. `display`는 읽기 전용 StateFlow다. 화면은 이를 구독해 `MotionSpeedometer`로 그리며, 화면 재구성·탭 이동·회전 때문에 소유 객체를 다시 만들지 않는다. 객체가 살아 있는 동안 구독자가 없어도 마지막 숫자를 유지한다. 새 산책은 새 객체로 시작한다. 프로세스 사망 뒤 현재 속도를 임의 복원하는 기능은 없다.

`MotionDisplayReducer`는 Android·DB·GPS·실제 시계에 의존하지 않는다. 전달받은 단조 시각만 사용한다. 원본·거리·기록 시간·인증 정책을 수정하거나 표시 속도를 적분하는 경로는 없다.

일시정지·종료 버튼과 상단 산책 상태 문구는 이 컴포넌트에 없다. `onLifecycle`은 실행층에서 이미 결정한 상태를 전달하는 알림이며 기록을 제어하는 명령이 아니다. `FINAL`도 저장 완료 영수증이 아니다.

## 5차에서 연결할 입력 계약

- 실행층은 `sessionId`, 단조 시계 영역, 구독 source, 증가하는 generation, 활성 구간 시작 시각을 제공한다. `onTick`의 시각은 현재 epoch의 clock 기준이다.
- 새 source·재개는 증가하는 generation과 새 sourceId로 `onSourceChanged`를 호출한다. 같은 clock이면 시작 시각은 이전 표시 처리 시각 이상이어야 한다. 다른 clock이면 이전 시각과 뺄셈하지 않는다. 종료된 객체는 재개하지 않는다.
- `DisplaySpeedSample`은 **이동 엔진에서 표시 가능하다고 인정한 속도**를 전달한다. null은 근거 없음이고 0은 실제 측정된 정지다. 표시층이 좌표로 속도를 계산하거나 임의의 작은 속도를 0으로 바꾸지 않는다.
- #294의 `MotionEstimate`를 연결할 때 `ref.sessionId/sourceEpoch/clockEpochId`, `observedElapsedNanos`, `speedMps`, `speedSource`, `speedQuality`, 제외 이유를 함께 확인한다. UNKNOWN·무효·mock·충돌·활동 구간 밖·역행 근거는 표시 가능 속도로 승격하지 않는다. UNVERIFIED 근거의 허용 여부도 어댑터에서 명시하고 테스트한다. 단순히 speedMps가 non-null이라는 이유로 통과시키지 않는다.
- 이 PR은 미병합 #294의 타입을 복사하거나 종속하지 않는다. 엔진 출력→표시 입력 어댑터, runtime 생성/해제, 직렬 이벤트·tick 공급, 기존 화면 교체는 5차다.

## 숫자와 수신 상태의 별도 전환

| 입력/상황 | 숫자 | 표시 |
|---|---|---|
| 새 세션 | 0.0 | INITIAL / 측정 대기 |
| 첫 유효 속도 | 즉시 갱신 | LIVE / 수신 중 |
| 결측·짧은 공백 | 마지막 값 유지 | HELD, 수신 표시 유지 |
| 장기 공백 | 마지막 값 유지 | STALE / 수신 불안정 |
| 회복 중 유효 속도 | 새 값으로 갱신 | 수신 불안정 유지, 안정 회복 후 전환 |
| 신뢰 가능한 0 | 즉시 0 | 경고 복귀 대기와 별개로 숫자·바늘 갱신 |
| 외부 pause·종료 알림 | 마지막 값 유지 | PAUSED / FINAL |
| 외부 재개 알림 | 이전 값 유지 | 새 source의 측정 대기 |

`freshness`는 측정 최신성이고 `signal`은 안정화한 사용자 표시다. HELD/LIVE가 왕복해도 GPS 문구·점·보조 문구는 왕복하지 않는다. 긴 공백 이후에는 새 속도를 표시할 수 있으므로 보조 문구를 항상 ‘마지막 값 유지’로 쓰지 않고 ‘수신 불안정’으로 유지한다. 접근성 설명은 현재 측정과 유지값을 구분한다.

초기 실험 설정은 fresh 3초, stale 10초, 회복 5초, 회복 중 관측/도착 간격 최대 2초다. 거리 설정과 독립이며 **실기기에서 확정한 값이 아니다**. 회복은 새 유효 측정들이 관측 시각과 앱 처리 시각 양쪽에서 5초 이상 이어져야 한다. 결측이나 긴 관측/도착 간격은 회복 창을 끊는다. 관측 사이 간격과 도착 사이 간격은 따로 비교하므로 허용 최신성 범위 안의 일정한 전송 지연만으로 회복을 막지 않는다. tick만 진행하거나 한 묶음으로 과거 측정을 받는 것으로 정상으로 돌아가지 않는다.

유효 속도의 최신성은 도착 시각 대신 측정 시각으로 평가한다. 과거 배치는 원본 엔진에서 모두 처리하더라도 표시에서 오래된 숫자를 역재생하지 않는다. 한 batch는 최종 상태만 발행한다. 중복·역행·미래 측정·다른 세션·옛 source는 표시를 덮지 못한다. 마지막 숫자와 그 측정 시각·clock·출처는 계속 함께 유지한다.

## 화면과 검증 범위

`MotionSpeedometer`는 기존 지도 테마의 속도 색을 따르고 숫자·바늘·GPS 표시만 렌더링한다. 상태에 따라 레이아웃을 삽입/삭제하지 않으며, 글자 배율별로 영역 크기를 정한 뒤 모든 상태에 같은 크기를 사용한다. 숫자는 고정 폭, 한 줄이고 비현실적으로 큰 값은 화면에서만 `999+`로 제한한다. 바늘 보간은 Compose에만 있으며 정지 0은 보간을 기다리지 않는다.

선택 검증: reducer의 시간 경계·반복 흔들림·늦은 배치·실제 정지·source/clock/세션 경계, 세션 객체의 재구독과 배치 발행, Compose의 상태별 동일 bounds와 2배 글자 크기·재마운트. 기존 `WalkSpeedometerTest`를 함께 실행한다. 실제 화면 회전·탭 이동의 runtime 수명 연결과 기기 성능 검증은 5·6차에서 수행한다.
