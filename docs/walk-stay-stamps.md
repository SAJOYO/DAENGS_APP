# 머문 자리 스탬프 · 실험 정책 v1

휴대폰 관측이 작은 영역 안에서 이어졌다는 흔적을 남긴다. 반려견이 실제로 쉬었다는 자동 행동 기록은 아니다. 보호자 행동·체류 통계·산책 인정·거리 계산과 분리한다.

## 판정과 배치

| 조건 | 초기값 / 처리 |
| --- | --- |
| 후보 | 첫 유효 관측점을 고정 중심으로 사용 |
| 확정 | 중심에서 6m 이내 관측이 30초 이어짐 |
| 공백 | 관측 간격이 10초를 초과하면 후보 초기화 |
| 불확실 | 정확도 누락·비정상·10m 초과, mock, 좌표 오류, 역순·중복 시각, 좌표 속도 7m/s 초과는 연속 근거를 끊음 |
| 이탈 | 확정 중심에서 10m 밖의 유효 관측이 6초 이어짐 |
| 재방문 | 첫 장소 중심에서 6m 안이면 같은 산책의 기존 스탬프 유지 |
| 표시 | 후보 시작~확정 시각 안의 실제 표시 동선 정점 중 중심에서 6m 이내인 마지막 점 |
| 배치 불가 | 선이 없거나 해당 시간·장소의 정점이 없으면 표시 보류 |

확정 이후 스탬프 데이터에는 시작 위치·시각과 확정 시각만 남는다. 누적 시간, 방문 횟수, 초당 포인트 배열, 주기적 타이머는 없다. 이탈 확인에 필요한 상태 한 개와 새 후보 한 개만 유지한다. 메모리는 확인한 서로 다른 장소 수에 비례한다. 기존 원본 GPS 저장은 계속한다.

공백/일시정지는 후보와 진행 중 이탈 확인을 끊지만 이미 확인된 장소를 지우거나 이탈로 바꾸지 않는다. 다음 실제 관측으로 이탈이 확인되어야 다른 후보를 찾는다. 재방문해도 아이콘 크기·좌표·색을 갱신하지 않는다. 지도에 선이 아직 없는 경우 선이 생길 때까지 표시를 미룰 수 있다. 라이브 경로의 5,000점 보존 범위 밖으로 나간 스탬프는 화면에서 숨기며, 전체 완료 경로에서는 다시 배치할 수 있다.

## 데이터 흐름

- `WalkTrackingService`: 산책 구독에만 `minDistanceMeters=0` 요청. 기존 1.5초 간격/최소 0.75초 설정 유지. OS의 실제 수신 간격은 보장되지 않는다.
- 원본을 Room writer에 넘기고 `StayStampRecorder`에 입력한다. `TrailRecorder`의 3m 표시 필터는 그대로다. 일시정지/종료 후 늦게 배달된 fix는 기록하지 않는다.
- `WalkHistory.sessionDetail`: 저장 fix를 clientSeq 순서로 같은 판정기에 재생한다. chainIndex 변경은 연속 근거를 초기화한다.
- 판정은 저장되는 좌표·시각·accuracy·mock 필드만 사용한다. 저장하지 않는 Doppler 속도나 monotonic 시각에 의존하지 않는다.
- `composeMapScene`이 허용한 동선에서만 `anchorStayStamps`가 실제 정점을 고른다. 이후 시각의 좌표는 과거 스탬프를 이동시키지 않는다. 기존 경로 필터의 라이브/과거 속도 입력 차이로 표시 동선 자체가 다른 경우에는 배치 가능 여부도 달라질 수 있다.
- Naver 레이어: 목줄 강아지 56×34dp, 중앙 앵커. 탭하면 “머문 자리 · 휴대폰 위치로 추정” 캡션을 토글한다. 보호자 행동 편집기로 보내지 않는다.

서버 API/DB 마이그레이션은 없다. 다른 기기에서 원본 fix를 복원할 수 있을 때 같은 계산이 가능하다. 기존 기록에 관측이 드물거나 정확도가 없으면 스탬프를 만들어 채우지 않는다. 정책 변경 시 과거 기록도 현재 정책으로 다시 계산한다.

## 검증과 남은 확인

새 판정기 테스트: 정지 장기 입력, 고정 중심의 느린 이동, 수신 공백, 짧은 pause, 공백을 가로지른 이탈 금지, 같은 장소 재방문, 정확도/중복/튐, 3m 미만 원본, 저장 재생 일치.
배치 테스트: 같은 시간의 동선 정점, 미래 좌표로 이동 금지, 배치 근거 부재, 지도 목적별 표시, 보호자 기록 분리. Room 기록 조회도 작은 원본 관측에서 같은 스탬프가 나오는지 확인한다.

6/10m, 30/6/10초, 정확도 10m는 실기기 검증 전 실험값이다. 아주 느린 이동과 GPS 드리프트, 보행자의 머무름과 반려견 행동을 완전히 구분할 수 없다. 실기기에서 정지·서행·화면 꺼짐·재방문 시 수신/배터리와 실제 지도 배치를 확인해야 한다. 이번 작업에서는 기기 설치나 GPS 필드 테스트를 하지 않았다.

검증 결과: `:app:assembleDebug` 성공. 지정한 `StayStampRecorderTest` 10개, `StayStampMarkerTest` 3개, `WalkHistoryTest` 12개, `MapScenePolicyTest` 4개, `WalkTrackingTest` 4개 — 총 33개 통과. 전체 테스트 스위트는 실행하지 않았다. 생성 APK 안의 스탬프 WebP와 반입 원본 WebP의 SHA-256 일치를 확인했다.
