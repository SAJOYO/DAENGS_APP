# 산책 기록 탐색

산책 기록을 같은 조건으로 고른 뒤 `산책별` 목록이나 `모아보기` 지도에서 읽는 화면이다.
이번 단계는 공통 선택 계약과 실제 화면을 합성 기록으로 연결한다. 사용자 기록을 읽는
Room·서버 공급부와 일반 사용자 화면의 진입점은 아직 연결하지 않는다.

## 명칭과 화면 구조

- 상위 화면은 **산책 기록**, 하위 보기는 **산책별 / 모아보기**다.
- `산책별`은 산책 한 번의 제목·날짜·경로·요약을 목록으로 보여준다.
- `모아보기`는 같은 조건으로 고른 산책 전체의 흔적을 지도에 겹친다.
- **일기**는 장면을 선택하고 구성하여 내보내는 별도 결과물이다. 현재 화면이나 산책 목록을
  일기라고 부르지 않으며, 미완성 일기 탭도 노출하지 않는다.
- Cellophane은 내부 공간 모델 용어다. 사용자에게는 `산책 흔적`, `모아보기`로 표현한다.

## 공유하는 선택 조건

두 보기는 하나의 `WalkRecordsQuery`를 사용한다. 조회 조건과 결과 조건이 다르면 화면에
게시하지 않는다. 날짜·계절·출발 날씨·텍스트 판정은 기존 `WalkHistoryFilter`를 공유한다.

| 조건 | 의미 |
| --- | --- |
| 강아지 | 세션에 동행한 강아지 ID. 전체를 선택하면 강아지 조건을 적용하지 않는다. |
| 제목·메모 | 공급부가 제공한 현재 유효한 제목과 사용자 메모의 포함 검색. NFC 정규화·대소문자 무시를 적용하며 `%`, `_`도 일반 문자다. |
| 기간 | 산책 시작 시각을 기기 시간대의 날짜로 바꾸고 처음·마지막 날짜를 모두 포함한다. 전체, 최근 7일·30일, 날짜 지정이 있다. |
| 계절 | 같은 시작 날짜의 월 기준. 3–5월 봄, 6–8월 여름, 9–11월 가을, 12–2월 겨울이다. |
| 출발 날씨 | 저장된 WMO 코드의 맑음 / 흐림·안개 / 비 / 눈 / 정보 없음. 산책 도중의 환경을 추정하지 않는다. |

서로 다른 조건은 AND, 계절이나 날씨 안의 여러 선택은 OR다. 빈 선택은 해당 조건 전체다.
누락·알 수 없는 날씨를 맑음으로 바꾸지 않는다. 날짜 선택기가 주는 UTC 날짜 표현은
`LocalDate`로 읽고, 산책 시작 날짜를 판정할 때 사용하는 기기 시간대와 혼동하지 않는다.

키워드는 화면에서 최대 200자를 입력받고, 비어 있지 않을 때 250ms 지연 후 조회한다.
제목·메모 외의 세션 ID, 원본 JSON, 공간 셀이나 행동 코드를 검색 텍스트로 섞지 않는다.
기존 제목 유효성·삭제된 메모 제외·계정 소유권 확인은 실제 공급부를 연결할 때 지켜야 할
계약이며, 이번 합성 공급부가 그 저장소 검증까지 구현한 것은 아니다.

## 조건 편집과 상태 유지

`조건` 시트는 현재 조건의 **편집본**을 별도로 가진다. 강아지·기간·계절·출발 날씨를
누르는 동안 기존 결과를 바꾸지 않고, `적용`할 때 함께 반영한다. `취소`, 바깥 영역 탭,
시트 닫기는 편집본을 버린다. 날짜 창의 `날짜 선택`도 시트 편집본까지만 바꾸며 최종
조회는 시트의 `적용`을 따른다.

- 상단 검색어는 공유 조건을 직접 변경한다. 이전 조회를 취소하고 새 조건의 결과를 기다린다.
- 시트의 `조건 초기화`는 편집본의 강아지·기간·계절·날씨를 비우고 **검색어는 유지**한다.
  이것도 `적용` 전에는 현재 결과에 영향을 주지 않는다.
- 화면의 `초기화`와 빈 결과의 `전체 기록 보기`는 **검색어를 포함한 모든 조건**을 지운다.
- 보기 전환은 조회 조건·선택 집합·현재 목록 페이지를 바꾸지 않는다. 목록 스크롤과 지도
  카메라를 저장하여 같은 조건으로 되돌아올 때 사용한다.
- 조건을 실제로 바꾸면 첫 페이지로 돌아가고 목록 스크롤·지도 카메라를 초기화한다.
  선택한 보기 자체는 유지한다. 이전 조건의 기록이 새 조건 아래 잠깐 나타나지 않도록
  결과 상태도 함께 초기화한다.
- 로딩·오류·결과 없음에서도 검색과 조건 편집을 사용할 수 있다. 선택한 강아지가 현재
  강아지 목록에서 사라지면 강아지 조건을 전체로 되돌린다.

## 전체 선택과 페이지

`WalkRecordsSource.select(query)`는 `WalkRecordsSelection`을 반환한다. 후보는 공급부가
이미 저장할 만한 기록으로 인정한 산책이다. 공통 선택기는 종료되지 않은 후보를 제외하지만
새 `countsAsWalk` 문턱값을 적용하지 않는다. 행동 기록 때문에 보존된 짧은 산책도 검색할 수 있다.

선택기는 모든 후보에 조건을 적용한 다음 **시작 시각 DESC / 세션 ID DESC**로 정렬한다.
전체 `records`와 `sessionIds`를 확정한 뒤 목록을 다섯 건씩 나눈다. `page()`는 1–30건 크기를
받으며 범위 밖 페이지는 빈 목록이다. 현재 페이지의 다섯 건만 지도에 전달하지 않는다.

같은 ID가 두 번 들어오거나 기록 ID와 흔적의 산책 ID가 다르면 명시적으로 거부한다.
결과를 만든 뒤 호출자가 원본 목록·조건 집합·메모·경로·흔적 셀 집합을 변경해도 결과가
따라 바뀌지 않도록 선택 시 복사한다.

## 지도에 표시할 수 없는 기록

흔적이 없는 기록도 전체 선택 ID와 목록에 남는다. 지도는 전체 선택 중 비어 있지 않은
흔적을 계산하고, 실제 마스크가 만들어진 산책 수를 표시 수로 센다.

예를 들어 `선택 산책 12회 · 표시 흔적 11개`라면 나머지 한 건은 목록에서 읽을 수 있다는
안내를 함께 보여준다. 전부 흔적이 없어도 선택 결과를 빈 검색 결과로 바꾸지 않고
`표시할 산책 흔적이 없어요` 상태를 보여준다. 경로나 기준점으로 대체 흔적을 지어내지 않는다.

표시는 [산책 흔적 브러시 계약](walk-trace-brush.md)을 사용한다. 산책 한 장의 기본 알파는
고정되고 서로 다른 산책이 겹칠 때만 진해진다. 표시 마스크를 시간량·선호·행동 확률로
다시 해석하지 않는다. 계산 상한을 넘으면 일부 산책을 조용히 빼지 않고 지도 오류를 표시한다.
지도 계산 실패가 목록의 검색 결과를 지우지는 않는다.

## 이번 시연의 데이터 경계

`WalkRecordsLabActivity`는 debug manifest에만 등록되어 있다. 실제 `WalkRecordsScreen`과
Naver 지도 렌더러에 `WalkRecordsLabFixture`를 주입하며, 화면에 `가상 산책 12회 · 화면 시연`을
표시한다. 합성 기록은 2026-01-22부터 2026-09-09까지이고 시연 기준일은 2026-09-10이다.
두 강아지, 여러 계절·출발 날씨, 정보 없는 날씨, 흔적 없는 산책 한 건이 포함된다.

공급부는 메모리의 합성 기록을 읽는다. 로그인·Room·서버 조회나 사용자 기록 쓰기를 수행하지
않는다. 배경 지도는 실제 지도 SDK를 사용하므로 지도 인증과 네트워크는 별도다.
목록 선택 시 열리는 창도 합성 기록의 경로·요약·메모를 보여주는 시연용 창이며, 기존 실제
산책 상세 화면과의 연결을 완료했다는 의미가 아니다.

```powershell
adb shell am start -n com.daengs.app/.ui.walk.WalkRecordsLabActivity
```

## 후속 단계와 확인 범위

다음 Step3에서는 지도와 관련 산책 목록을 한 쌍으로 연결한다. 개별 기록을 살펴보면 해당
산책을 강조하되 선택 집합과 배경 흔적을 유지한다. 표시 숨김은 지도에서만 적용하고,
검색 조건을 변경하는 동작과 구분한다. 현재 모아보기에는 개별 강조·숨김·관련 목록이 없다.

Step4의 **행동 검색**은 별도다. 환경처럼 산책 전체에 붙은 조건과 달리 특정 순간의 행동
기록을 찾고, 위치 없는 행동도 결과에 남겨야 한다. 핀·기록 카드·관련 산책 흔적의 연결과
`기록 위치 / 산책 흔적` 보기는 그 단계에서 붙인다. 현재 제목·메모에 행동 이름을 입력하는
검색을 행동 코드 검색이나 행동 비교가 구현된 것으로 취급하지 않는다.

이번 단계의 확인 대상은 공통 필터·기간 경계·전체 선택과 페이지 분리·흔적 없는 기록 유지,
조건 편집의 적용/취소/초기화, 탭 전환과 상태 복원, 실제 지도 위 전체 선택 표시다.
