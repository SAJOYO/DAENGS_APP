# 산책 기록 탐색

산책 기록을 같은 조건으로 고른 뒤 `산책별` 목록이나 `모아보기` 지도에서 읽는 화면이다.
Step2에서 공통 선택 계약과 실제 화면을 합성 기록으로 연결했다. Step3에서는
`모아보기` 지도와 관련 산책 목록, 기록 선택·강조·지도 숨김을 구현하고 시연 검증을 마쳤다.
같은 Step3 범위에 `전체 흔적 / 겹친 구간`과 지도에서 구간을 골라 관련 산책을 읽는
확장을 추가했다. 이 확장의 확인 결과는 아래 이전 Step3 결과와 구분하여 기록한다.
Step4에서 같은 화면의 행동 기록 탐색을 구현했다. 겹침 색 표현에 이어 Step5에서 전체 조작
시연과 마감 리뷰까지 수행했다. 실제 데이터 연결 1단계에서 현재 로그인 계정의 Room 기록
공급부를 추가했다. 2단계에서는 서버의 봉인 원판을 모아보기의 기존 브러시에 연결했다.
일반 사용자 화면의 진입점·실제 상세 연결은 후속이다.

## 명칭과 화면 구조

- 상위 화면은 **산책 기록**, 하위 보기는 **산책별 / 모아보기**다.
- `산책별`은 산책 한 번의 제목·날짜·경로·요약을 목록으로 보여준다.
- `모아보기`는 같은 조건으로 고른 산책 전체의 흔적과 관련 산책 목록을 함께 보여준다.
  세로 화면은 지도 아래 목록, 넓은 화면은 지도 옆 목록으로 배치한다.
- **일기**는 장면을 선택하고 구성하여 내보내는 별도 결과물이다. 현재 화면이나 산책 목록을
  일기라고 부르지 않으며, 미완성 일기 탭도 노출하지 않는다.
- Cellophane은 내부 공간 모델 용어다. 사용자에게는 `산책 흔적`, `모아보기`로 표현한다.

## 공유하는 선택 조건

두 보기는 하나의 `WalkRecordsQuery`를 사용한다. 조회 조건과 결과 조건이 다르면 화면에
게시하지 않는다. 날짜·계절·출발 날씨·텍스트 판정은 기존 `WalkHistoryFilter`를 공유한다.

| 조건 | 의미 |
| --- | --- |
| 강아지 | 세션에 동행한 강아지 ID. 전체를 선택하면 강아지 조건을 적용하지 않는다. |
| 제목·메모 | 공급부가 제공한 현재 유효한 제목과 사용자 메모의 포함 검색. NFC 정규화·대소문자 무시를 적용하며 `%`, `_`도 일반 문자다. |
| 기간 | 산책 시작 시각을 기기 시간대의 날짜로 바꾸고 처음·마지막 날짜를 모두 포함한다. 전체, 최근 7일·30일, 날짜 지정이 있다. |
| 계절 | 같은 시작 날짜의 월 기준. 3–5월 봄, 6–8월 여름, 9–11월 가을, 12–2월 겨울이다. |
| 출발 날씨 | 저장된 WMO 코드의 맑음 / 흐림·안개 / 비 / 눈 / 정보 없음. 산책 도중의 환경을 추정하지 않는다. |

서로 다른 조건은 AND, 계절이나 날씨 안의 여러 선택은 OR다. 빈 선택은 해당 조건 전체다.
누락·알 수 없는 날씨를 맑음으로 바꾸지 않는다. 날짜 선택기가 주는 UTC 날짜 표현은
`LocalDate`로 읽고, 산책 시작 날짜를 판정할 때 사용하는 기기 시간대와 혼동하지 않는다.

키워드는 화면에서 최대 200자를 입력받고, 비어 있지 않을 때 250ms 지연 후 조회한다.
제목·메모 외의 세션 ID, 원본 JSON, 공간 셀이나 행동 코드를 검색 텍스트로 섞지 않는다.
Room 공급부는 기존 제목 유효성·삭제된 메모 제외·계정 소유권 확인을 거친 실제 저장
텍스트를 제공한다. debug 시연용 합성 공급부와 일반 사용자 진입점은 이 계약과 구분한다.

## 실제 데이터 연결 1단계 · Room 기록 공급

`DaengsApp.walkRecordsSource()`는 현재 로그인에 고정된 `WalkRecordsSource`를 만든다.
미로그인·빈 회원 ID에서는 null이다. 호출 화면은 로그인 scope별로 한 번 만들어 보관하고,
계정이 바뀌면 화면 저장 상태까지 새 scope로 분리해야 한다. 기존 운영 진입점 교체는 후속이다.

- `RoomWalkRecordsSource`는 완료된 해당 계정의 산책 전체를 읽는다. 강아지·기간·계절·
  날씨·현재 제목·메모 조건을 적용한 결과를 확정한 뒤 화면에서 페이지를 나눈다.
- 산책·강아지 연결·행동·사진·사진 동기화 상태·분석·GPS는 한 Room transaction의 snapshot이다.
  조건에 맞는 산책만 경로를 요약하며, 요약과 썸네일 축약은 기존 기록 목록 규칙을 재사용한다.
- 현재 행동 행의 변환을 그대로 사용한다. 삭제 행은 노출하지 않고 위치 없는 행동과 추정·정정된
  핀은 원본의 상태를 보존한다. 짧아도 행동·메모·사진이 남은 산책은 기존 기록 기준으로 유지한다.
- 제목은 현재 행동과 사진의 지문에 유효한 분석 결과만 사용한다. 예전 제목이나 삭제된 메모가
  검색으로 되살아나지 않으며, 사진 동기화 ACK만 바뀌어도 다시 판정한다.
- 공급부의 `changes`는 최초 조회와 7개 입력 테이블의 변경을 알린다. 화면은 같은 조건으로
  재조회하며, 읽는 동안 이전 결과를 비우고 취소된 조회 결과를 게시하지 않는다.
- 로그인·로그아웃 세대 변경도 Room 변경과 무관하게 조회를 무효화한다. 같은 회원으로
  재로그인해도 이전 공급부는 다시 유효해지지 않는다. 정상 토큰 refresh는 이 세대를 바꾸지 않는다.

로컬 `select()`의 `trace`는 null이다. 1단계에서는 원판 조회 없이 Room 기록만 제공했다.
2단계의 별도 조회에서도 GPS 경로로 공간 원판을 지어내지 않는다.

## 실제 데이터 연결 2단계 · 산책별 원판 공급

모아보기를 처음 열면 로컬에서 확정한 산책 집합 S의 전송된 `client_session_id`만
`POST /app/walks/spatial-diary/sheets/query`로 보낸다. 서버가 강아지·기간 조건을 다시
해석하지 않는다. 원판과 서버 Walk ID를 요청 당시 Room 매핑과 대조한 뒤 로컬 sessionId로
브러시에 전달한다. 목록 페이지·행동 기록·선택 집합은 원판 조회로 바뀌지 않는다.

- 서버는 현재 계정의 산책당 최신 봉인 원판 한 장을 같은 read-only REPEATABLE READ
  snapshot에서 읽는다. fingerprint와 중복 메타데이터를 검증하고 기존 payload를 반환한다.
  미봉인은 `pending`, 현재 계정에서 찾을 수 없는 산책은 `unavailable`이다. 봉인됐지만
  원판이 손상된 경우에는 오류를 반환하며 이전 원판으로 대신하지 않는다.
- 앱은 응답 순서·소속·버전·정수 셀 좌표·중복·범위·양수 peak를 검증한다. occupancy가
  0이어도 peak가 양수인 셀은 남긴다. 농도 값을 다시 계산하지 않고 기존 브러시의 고정
  알파·겹침 색을 사용한다. 생성 정책이 다르면 개별 표시만 허용하고 겹침 비교는 막는다.
- 원판 준비 중에도 로컬 경로·행동 위치·카드는 유지한다. 조회 대기·빈 원판·전송 확인 필요·
  서버 계산 대기·미지원·실패를 구분하고, 실패한 결과를 ‘흔적 없음’으로 표시하지 않는다.
- 같은 선택의 탭 왕복은 재조회하지 않는다. 새로고침은 서버 원판을 다시 읽으며 예전
  원판을 최신 결과처럼 유지하지 않는다. 조회 중 로그아웃·같은 회원 재로그인·로컬 기록
  수정/삭제/서버 ID 변경이 일어나면 늦은 응답을 게시하지 않는다.
- 요청은 최대 400개, 서버 원시 셀 합계는 100,000개다. 앱은 현재 paint 2·hex-v1·반지름
  4–64u·원판당 5,000셀을 지원한다. 기존 브러시의 타일/범위 상한도 유지한다.
  초과 결과를 조용히 일부만 잘라 보여주지 않는다.

APP [#271](https://github.com/SAJOYO/DAENGS_APP/pull/271)은 Room 공급부
[#269](https://github.com/SAJOYO/DAENGS_APP/pull/269) 위에 쌓았다. 서버 API는
DEV [#422](https://github.com/SAJOYO/DAENGS_dev/pull/422)에 있다. 이 단계는 DB
스키마·마이그레이션·전송/분석 작업을 바꾸지 않으며 배포를 포함하지 않는다.
운영 진입점과 실제 산책 상세를 연결하고 배포 API로 확인하는 것은 3단계다.

## 조건 편집과 상태 유지

`조건` 시트는 현재 조건의 **편집본**을 별도로 가진다. 강아지·기간·계절·출발 날씨를
누르는 동안 기존 결과를 바꾸지 않고, `적용`할 때 함께 반영한다. `취소`, 바깥 영역 탭,
시트 닫기는 편집본을 버린다. 날짜 창의 `날짜 선택`도 시트 편집본까지만 바꾸며 최종
조회는 시트의 `적용`을 따른다.

- 상단 검색어는 공유 조건을 직접 변경한다. 이전 조회를 취소하고 새 조건의 결과를 기다린다.
- 시트의 `조건 초기화`는 편집본의 강아지·기간·계절·날씨를 비우고 **검색어는 유지**한다.
  이것도 `적용` 전에는 현재 결과에 영향을 주지 않는다.
- 화면의 `초기화`는 검색어와 행동을 포함한 모든 조건을 지운다. 산책이 없는 결과의
  `전체 기록 보기`는 검색어를 포함한 **공통 산책 조건**만 지우고 행동 선택은 유지한다.
- 보기 전환은 조회 조건·선택 집합·현재 목록 페이지를 바꾸지 않는다. 목록 스크롤과 지도
  카메라를 저장하여 같은 조건으로 되돌아올 때 사용한다.
- 모아보기에서 고른 산책 ID·지도 숨김 ID 집합·관련 목록 스크롤·카메라도 현재 조회 조건에
  속한 표시 상태다. 탭 왕복과 화면 재생성에 유지하고, 상세 창을 열었다 닫아도 유지한다.
- 조건을 실제로 바꾸면 첫 페이지로 돌아가고 목록 스크롤·지도 카메라를 초기화한다.
  고른 산책과 숨김 상태도 비운다. 선택한 보기 자체는 유지한다. 이전 조건의 기록이 새
  조건 아래 잠깐 나타나지 않도록 결과 상태도 함께 초기화한다. 서로 다른 조회 조건의
  표시 상태를 무제한으로 보관하는 조건별 캐시는 아니다.
- 로딩·오류·결과 없음에서도 검색과 조건 편집을 사용할 수 있다. 선택한 강아지가 현재
  강아지 목록에서 사라지면 강아지 조건을 전체로 되돌린다.

## 전체 선택과 페이지

`WalkRecordsSource.select(query)`는 `WalkRecordsSelection`을 반환한다. 후보는 공급부가
이미 저장할 만한 기록으로 인정한 산책이다. 공통 선택기는 종료되지 않은 후보를 제외하지만
새 `countsAsWalk` 문턱값을 적용하지 않는다. 행동 기록 때문에 보존된 짧은 산책도 검색할 수 있다.

선택기는 모든 후보에 조건을 적용한 다음 **시작 시각 DESC / 세션 ID DESC**로 정렬한다.
전체 `records`와 `sessionIds`를 확정한 뒤 목록을 다섯 건씩 나눈다. `page()`는 1–30건 크기를
받으며 범위 밖 페이지는 빈 목록이다. 현재 페이지의 다섯 건만 지도에 전달하지 않는다.

같은 ID가 두 번 들어오거나 기록 ID와 흔적의 산책 ID가 다르면 명시적으로 거부한다.
결과를 만든 뒤 호출자가 원본 목록·조건 집합·메모·경로·흔적 셀 집합을 변경해도 결과가
따라 바뀌지 않도록 선택 시 복사한다.

## 지도에 표시할 수 없는 기록

이 절은 행동을 선택하지 않은 일반 모아보기의 표시 계약이다.
흔적이 없는 기록도 전체 선택 ID와 목록에 남는다. 지도는 전체 선택 중 비어 있지 않은
흔적을 계산하고, 실제 마스크가 만들어진 산책 수를 표시 수로 센다.

예를 들어 `선택 산책 12회 · 표시 흔적 11개`라면 나머지 한 건은 목록에서 읽을 수 있다는
안내를 함께 보여준다. **흔적 없음**과 사용자가 선택한 **지도에서 숨김**은 다른 상태다.
흔적이 없는 기록도 카드 선택과 `이 산책 보기`를 사용할 수 있고, 실제 저장 경로가 있으면
그 경로를 강조할 수 있다. `지도에서 숨기기`는 비활성화한다. 경로나 기준점으로 대체
흔적을 지어내지는 않는다.

전부 흔적이 없어도 선택 결과를 빈 검색 결과로 바꾸지 않는다. 실제 경로가 있으면 지도와
목록을 유지하여 경로를 살펴볼 수 있고, 흔적·경로 모두 없으면 `지도에 표시할 위치가 없어요`
상태를 보여준다. 카드에서는 표시 가능 여부가 확인되기 전까지 `지도 표시 확인 전`으로
표시하며, 아직 확인하지 않은 기록을 `지도 흔적 없음`으로 판정하지 않는다. 지도 전체의
준비 상태 문구와 개별 카드의 표시 가능 여부는 구분한다.

표시는 [산책 흔적 브러시 계약](walk-trace-brush.md)을 사용한다. 산책 한 장의 기본 알파는
고정되고 서로 다른 산책이 겹칠 때만 진해진다. 표시 마스크를 시간량·선호·행동 확률로
다시 해석하지 않는다. 계산 상한을 넘으면 일부 산책을 조용히 빼지 않고 지도 오류를 표시한다.
지도 계산 실패가 목록의 검색 결과를 지우지는 않는다.

## 지도와 관련 산책을 함께 읽기

행동을 선택하지 않은 일반 모아보기의 기본 관련 목록은 현재 페이지가 아닌
**전체 선택 records**를 사용한다. 겹침 구간을 고르면
그 구간의 전체 근거 ID에 해당하는 산책을 보여주되 원래 조회 집합은 유지한다. 제목·날짜·
강아지·시간·거리와 기존 경로 썸네일을 보여주고 카드 선택을 지도 강조와 연결한다.

| 조작 | 지도와 목록의 변화 | 유지하는 것 |
| --- | --- | --- |
| 카드 선택 | 해당 카드를 선택하고 저장된 실제 경로를 강조한다. 숨기지 않은 산책에 경로가 있으면 카메라를 그 경로에 맞춘다. | 조회 조건·전체 선택 ID·다른 산책의 배경 흔적 |
| 선택한 카드 다시 누르기 / 강조 해제 | 카드 선택과 경로 강조를 해제한다. | 카메라 위치·배율, 배경 흔적 |
| 지도에서 숨기기 | 해당 산책의 흔적과 경로 강조를 지도에서 숨기고, 카드에는 숨김 상태를 표시한다. | 검색 결과·선택 산책 수·관련 목록·카메라 |
| 지도에 다시 표시 / 모두 표시 | 숨김을 해제하여 해당 흔적을 합성에 다시 포함한다. | 조회 조건·목록·카메라 |
| 이 산책 보기 | 선택 카드의 `onOpen(sessionId)`를 호출한다. | 뒤에 남아 있는 탐색 화면의 조건·선택·숨김·스크롤·카메라 |

카드를 누르는 것과 상세를 여는 것은 별개다. 숨긴 카드를 골라도 숨김을 자동으로 풀지 않고,
그 선택 때문에 지도를 이동시키지 않는다. 표시 중인 카드의 명시적인 선택만 해당 실제
경로로 카메라를 맞춘다. 숨김·복원·강조 해제는 새로운 카메라 맞춤 요청을 만들지 않는다.
사용자가 지도를 움직이는 동작도 검색 조건이나 배경 산책 집합을 바꾸지 않는다.

예를 들어 흔적이 있는 11회 중 2회를 숨기면 `선택 산책 12회 · 표시 흔적 9개`로 바뀐다.
`숨김 2회 · 흔적 없음 1회`를 구분해 안내하며 목록은 12회를 유지한다. 모든 흔적을 숨겨도
지도 자체를 없애거나 빈 검색 결과로 바꾸지 않는다. 현재 카메라와 관련 목록을 유지하고
`모두 표시`로 돌아올 수 있게 한다.

## 전체 흔적과 겹친 구간

`전체 흔적 / 겹친 구간`은 조회 조건이 아닌 지도 표시 방식이다. 겹친 구간에서는
`최소 2회 / 3회 / 5회`를 선택한다. 기본 알파는 0.14, 최종 픽셀 상한은 0.40으로 고정하고
산책 수나 조회 최대값으로 정규화하지 않는다.

전체 흔적은 기존 단색을 유지한다. 겹친 구간은 **2회 청록 / 3–4회 노랑 / 5회 이상 주황**의
고정 색 기준을 사용하며 화면에 범례를 표시한다. 최소 횟수를 바꿔도 같은 구간의 색을
재정규화하지 않는다. 원본 셀의 색 사이를 부드럽게 보간하며, 정확한 산책 수는 구간을
눌렀을 때 원본 근거에서 읽는다. 색의 의미는 반복 산책이지 체류·선호·행동 빈도가 아니다.
숨김은 표시 알파와 영역에만 관여하고, 전체 조회에서 정한 색 기준을 바꾸지 않는다.

겹침 횟수는 전체 조회의 같은 반지름 원본 셀에 연결된 서로 다른 산책 ID 수다. 최소
횟수를 만족하면서 **그 셀의 원본 참여 산책이 하나라도 표시 중인 셀**의 부드러운 마스크로
표시 합성을 제한한다. 참여 산책을 모두 숨긴 셀에 주변 브러시가 번져 남지 않게 한다.
숨김은 칠할 산책·표시 마스크·새로 누를 수 있는 지점에만 영향을 주며 원래 겹침 기준과
구간의 전체 근거 ID는 바꾸지 않는다.
반지름 혼합이나 겹침 전용 상한 초과는 겹친 구간만 사용 불가로 처리한다. 전체 흔적과
기본 관련 목록은 계속 사용할 수 있다.

| 조작 | 동작 |
| --- | --- |
| 전체 흔적에서 지도 누르기 | 구간을 선택하지 않는다. |
| 겹친 구간에서 지도 누르기 | 원본 기준 셀 한 곳을 선택해 중심 표식과 그 셀의 전체 관련 산책을 보여준다. 숨긴 산책도 근거 목록에 남는다. |
| 같은 구간 다시 누르기 | 같은 근거 목록의 맨 위로 돌아간다. |
| 해당 구간 없음 | 이전 구간 선택을 지우고 전체 목록과 안내 문구를 보여준다. |
| 전체 목록 | 구간·카드 선택을 해제하고 원래 조회의 전체 목록으로 돌아간다. |
| 전체/겹침 방식 또는 최소 횟수 변경 | 구간·카드 선택을 해제한다. 숨김·카메라·공통 조회 조건은 유지한다. |

누른 위치가 기준 셀 밖이면 셀 영역까지 최대 **12 Web Mercator u** 이내에서 가까운
셀을 찾는다. 반환하는 근거는 한 셀의 전체 ID 집합이며 이웃 셀들의 ID를 합치지 않는다.
이것은 원판에 겹쳐 기록된 영역에 대한 조회다. 실제 시설 방문이나 행동 확률을 추론하지
않는다. 구간 선택과 별개로 카드를 명시적으로 고르면 해당 실제 경로를 강조하고 맞춘다.

보기 방식·최소 횟수·선택 구간·숨김·카메라는 같은 조건에서 탭 왕복과 저장 상태 복원에
유지한다. 공통 조건을 바꾸면 이 표시 상태까지 초기화한다. 지도 이동은 조회를 바꾸지 않는다.

## 마스크 준비와 지도 표시 갱신

`prepareWalkRecordsTraces(selection)`은 전체 선택의 산책별 표시 마스크와 초기 지도 범위를
준비한다. 초기 범위에는 저장된 실제 경로도 포함하므로 흔적이 없는 산책 역시 살펴볼 수
있다. `PreparedWalkRecordsTraces`는 준비된 마스크를 내부에 보관하고, `availableWalkIds`로
표시할 수 있는 산책을 구분한다.

같은 조회 결과에서 숨김 집합만 바뀌면 산책별 마스크를 다시 만들지 않고
`compose(hiddenIds, minimumOverlapWalks)`만 실행한다. 겹침 표시 마스크는 최소 횟수와
해당 기준에 영향을 주는 숨김 ID 집합별로 준비하며 최대 6상태·합계 256타일을 재사용한다.
카드 선택·강조 해제는 마스크 준비나 배경 합성을 다시 실행하지 않는다. 전체
범위도 숨김 집합으로 다시 계산하지 않는다. 개별 경로로 카메라를 맞추는 요청은 별도
`walkRecordFocusBounds(record)`와 요청 번호를 사용한다.

합성이 진행 중이거나 실패하면 이전 숨김 상태의 흔적을 그대로 보여주지 않는다. 지도는
유지하면서 진행·오류 상태를 알리고, 관련 목록과 상세 열기는 사용할 수 있게 한다.
조건이 바뀌면 이전 조회의 준비 작업·합성을 취소하고 새 전체 선택으로 다시 준비한다.
계산은 백그라운드에서 수행하며 취소 확인과 브러시의 셀·타일 상한을 유지한다.

## 이번 시연의 데이터 경계

`WalkRecordsLabActivity`는 debug manifest에만 등록되어 있다. 실제 `WalkRecordsScreen`과
Naver 지도 렌더러에 `WalkRecordsLabFixture`를 주입하며, 화면에 `가상 산책 12회 · 화면 시연`을
표시한다. 합성 기록은 2026-01-22부터 2026-09-09까지이고 시연 기준일은 2026-09-10이다.
두 강아지, 여러 계절·출발 날씨, 정보 없는 날씨, 흔적 없는 산책 한 건이 포함된다.
겹침 확장용 fixture도 12회·흔적 11개와 메타데이터를 유지한다. 첫 두 전체 경로는 유지하고
나머지에는 기존 경로 일부의 왕복을 섞었다. 공통 시작부는 9–11회, A 바깥쪽은 3–4회,
B 바깥쪽은 2–3회가 공유되도록 구성해 최소 횟수에 따라 다른 영역을 볼 수 있게 했다.
흔적 셀은 선택한 실제 합성 경로를 지상 거리 약 2m 간격으로 보간해 만들고 고립점은
별도 구간으로 둔다. 실제 Naver 지도에서 최소 2·3·5회로 높일수록 표시 영역이 줄어드는
것을 확인했다.

공급부는 메모리의 합성 기록을 읽는다. 로그인·Room·서버 조회나 사용자 기록 쓰기를 수행하지
않는다. 배경 지도는 실제 지도 SDK를 사용하므로 지도 인증과 네트워크는 별도다.
산책별 목록의 카드 또는 모아보기에서 `이 산책 보기`를 누르면 기존 debug 시연용
`SampleWalkRecordDialog`가 합성 기록의 경로·요약·메모를 보여준다. 실제 산책 상세 화면과의
연결을 완료했다는 의미가 아니다.

```powershell
adb shell am start -n com.daengs.app/.ui.walk.WalkRecordsLabActivity
```

## 후속 단계와 확인 범위

Step3의 지도·목록·강조·숨김에 겹침 구간 탐색을 연결하고 자동 검증과 실제 지도 시연을
마쳤다. 새 확장의 확인 범위는 아래에 따로 기록한다. 이전 Step3 테스트·캡처는 당시 기본 탐색의

## 모아보기의 행동 기록

공통 조건으로 선택한 산책 S는 그대로 두고, 조건 패널의 **행동 기록**에서 킁킁·배설·짖기
한 종류를 선택한다. 행동 선택도 편집본이므로 `취소`하면 적용하지 않는다. 새 행동을 적용하면
모아보기로 이동한다. 행동은 산책별 목록을 필터링하지 않으며, 탭을 왕복해도 선택값을 유지한다.
모아보기 상단에서 `행동 해제`를 누르면 공통 조건을 유지한 전체 산책 탐색으로 돌아간다.

`WalkRecord.entries`는 공급부가 현재 유효하다고 확정한 기록 원본이다. `WalkRecordsSelection`은
이 목록도 복사한다. `selectWalkRecordBehaviors(S, behavior)`는 S의 전체 산책에서 행동 코드와
반려견 귀속을 확인하여 기록 E를 선택한다. 특정 강아지를 골랐다면 `entry.petId`가 정확히
일치해야 한다. 전체 강아지에서는 미지정 기록도 남기고 카드에 `강아지 미지정`으로 표시한다.
메모는 행동 검색에 포함하지 않으며 기록 시각 역순·안정 키 순으로 정렬한다.
기간은 S의 산책 시작 날짜 기준이며, 자정을 넘긴 산책의 행동 시각을 다시 기간으로 거르지 않는다.

관련 산책 B는 E에 속한 산책을 한 번씩만 고르고 S의 순서를 유지한다. S의 현재 페이지,
행동 좌표 유무, 공간 흔적 유무는 행동 검색 조건이 아니다. 원판을 요구하는 기존 행동 비교
API를 이 조회에 재사용하지 않는다. 선택 결과는 현재 조회의 결과이며 행동 성향의 추론이 아니다.

| 보기 | 지도 내용 | 아래 목록 |
| --- | --- | --- |
| 기록 위치 | E 중 표시 가능한 행동 위치 | 위치 없는 기록까지 포함한 E |
| 산책 흔적 | B의 표시 가능한 흔적과 행동 핀, 선택 기록의 산책 경로 | 같은 E |

행동을 처음 선택하면 `기록 위치`로 시작하고, 행동 종류만 변경하면 사용자가 고른 보기를
유지한다. 공통 산책 조건을 변경하면 행동 종류는 유지하고 표시 방식·선택·숨김·카메라를
초기화한다. 탭 왕복·상세 창 복귀·저장 상태 복원에는 현재 표시 상태를 유지한다.

핀이나 기록 카드를 누르는 것은 강조와 위치 확인이며 상세 이동이 아니다. `이 산책 보기`가
해당 sessionId의 상세를 연다. 같은 좌표의 기록은 대표 핀과 기록 개수로 표시하고 전체 기록은
목록에 남긴다. 대표 핀을 반복 누르면 같은 좌표의 기록을 순환 선택하고 해당 카드로 스크롤한다.
선택된 기록을 대표 핀에 반영한다. 서로 다른 원본 좌표를 임의로 이동시키거나
가까운 위치의 기록 수를 행동 확률로 바꾸지 않는다.

표시 좌표는 명시적인 `ActionPin`이 있으면 그 point를 따른다. point가 null인 핀을 원본 GPS로
되살리지 않으며, 핀 객체 자체가 없을 때만 원본 위치를 사용한다. `추정 위치` 등 원래 위치
설명도 카드에 남긴다. 위치 없는 기록은 목록·상세에 유지하고 지도 좌표를 만들어내지 않는다.

숨김은 산책 단위로 그 산책의 핀·흔적·강조 경로에 적용한다. E·B와 기록 수는 유지하고
표시 수만 갱신한다. 같은 산책에 기록이 여러 건이어도 흔적 한 장만 합성한다. 행동 기록 수,
관련 산책 수, 위치를 표시하는 기록 수, 흔적 표시 수와 누락 사유를 구분한다. 이 단계의
행동 흔적 보기는 B 전체를 제공하며 2·3·5회 겹침 구간 탐색은 일반 모아보기에서 제공한다.
