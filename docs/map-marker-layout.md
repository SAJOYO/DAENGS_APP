# 지도 밀집 표식의 공통 정책

## 완료 산책의 분리 배치 (#417)

사용자가 승인한 완료 산책에는 `MapScene.detachedDiaryPins`를 켠다. 아래 기존
`placeMapMarkers`의 48dp/겹침 허용 폴백은 다른 지도에 유지하고, 완료 산책은
`placeDetachedMarkers`와 `NaverDetachedMomentLayer`를 사용한다.

- 장면과 행동을 한 번에 배치한다. 묶음은 같은 종류끼리만 만들고 원본 ID/시각/좌표/개수를 보존한다.
- 실제 위치에는 흰 테두리 안의 진한 점, 떨어진 객체에는 꼬리 없는 장면 번호 또는 기존 행동 그림/건수 배지를 사용한다.
  행동 그림도 장면과 같은 둥근 사각 프레임 안에 넣고 테두리/배경/선택 강조/배지 위치를 공유한다.
  여러 행동 종류가 묶이면 각 그림을 보존하며 같은 프레임 안에 담는다.
  위치 점은 기본 지름 13dp, 선택 시 16dp와 옅은 바깥 원으로 강조한다. 선택해도 기준 좌표는 같다.
  점과 객체는 흰 바탕선 위의 중립색 선으로 연결하며, 점을 눌러도 객체와 같은 기록을 선택한다. 저장 좌표는 변경하지 않는다.
- 선택 때의 최대 그림 크기를 미리 확보한다. 경로와 7dp, 다른 표식/고정 장애물과 4dp 간격을 둔다.
  현재 화면의 제어 버튼, 설정 버튼의 세로 위치, 서랍, 시작·끝/공백/머문 자리의 크기를 계산에 넣는다.
- 기존 유효 위치 → 가까운 후보 → 최대 두 이웃 재배치 → 최대 96dp 후보를 탐색한다.
  그래도 부족하면 같은 종류 묶음의 최대 지름을 44→60→80dp로 늘려 비교한다.
  연쇄 병합하지 않고 구성원끼리의 최대 거리를 제한한다.
- 공간 부족 결과는 `crowded`로 반환하며 지도에 겹쳐 그리지 않는다. `unplacedIds`로 누락을 전달하고
  장면 목록의 지도 밖 표시/행동 기록 목록으로 접근한다. 지도 밖 좌표도 기존 목록에 남는다.
- 카메라 이동 중에는 네이티브 표식이 지도를 따라 움직이고 정지 뒤에 재배치한다.
  유효한 이전 오프셋을 먼저 재사용하며, 선택만 바뀌면 최대 크기 예약 때문에 자리를 유지한다.
- 시작·끝은 실제 경로 끝점 위의 `산책 시작` / `산책 끝` 표식이다. 기존 12m 이내 끝점 통합은
  `산책 시작·끝`으로 표시한다. 시작/끝 원본 장면은 일반 번호와 본문 목록에서 제외하지만 저장된 내용은 지우지 않는다.
  둥근 사각형 아래의 세모 꼬리 끝을 실제 좌표에 고정하며 별도의 점/연결선은 붙이지 않는다.
  배치 계산에도 꼬리를 포함한 높이와 하단 중앙 기준점을 동일하게 사용한다.
  판별은 source ID/세션 한정 ID로 하며 수정 가능한 제목이나 첫째·마지막 순서로 추측하지 않는다.
- 행동 원본은 같은 일기 갱신의 `sourceEntries`에서 읽는다. v2 pin이 있으면 그 표시 좌표를 쓰며
  unlocated를 과거 GPS로 대체하지 않는다. 메모는 행동 그림으로 중복 생성하지 않는다.

`WalkDetachedPinsLabActivity`는 `.routepreview` 별도 앱에서만 여는 메모리 가상 기록이다.
일반/밀집 12건을 전환하여 실제 `WalkDiaryMapForAccount`와 네이버 공급자를 확인한다.
후속 승인된 4단계에서는 기존 재생 시간축에 맞춰 현재 장면/행동의 선택 강조를 투영한다.
원본 좌표와 묶음 ID를 유지하며 체크포인트 사이의 매 틱마다 배치 입력을 바꾸지 않는다.

## 기존 다른 지도

행동 핀과 일기 장면은 `map/layout/MapMarkerLayout.kt`의 화면 좌표 계산을 함께 사용한다. 실제 기록을 같은 장소로 취급하는 기존 5m 행동 정책은 변경하지 않는다. 지도 묶음은 표시용이며 원본 ID, 시각, 좌표, 기록 수를 보존한다.

## 묶음과 배치

- `clusterMapMarkers`: 네이버 투영을 dp로 바꾼 뒤 기본 최대 지름 44dp로 묶는다. 묶음 안의 모든 점 사이 거리를 제한해 이웃을 따라 길 전체가 연쇄 병합되지 않게 한다. 동일 좌표는 확대해도 함께 남는다. 중심에 가까운 실제 구성원 위치를 기준점으로 쓴다.
- `placeMapMarkers`: 실제 비트맵의 폭·높이와 꼬리/중앙 기준점을 받아 배치한다. 열람 중인 장면 → 선택 묶음의 나머지 장면 → 일반 표식 순으로 놓으며 같은 우선순위는 화면 위치순으로 처리한다. 최종 겹침 순서에도 같은 우선순위를 적용한다. 표시 사각형 사이 간격은 4dp, 기준점에서 최대 이동은 48dp다. 화면 경계·하단 패널·상단 제어·출발/도착 표식을 피할 후보를 찾는다. 표시 위치를 옮기면 실제 기준점까지 연결선을 그린다.
- 물리적으로 공간이 부족하면 `crowded` 결과를 명시적으로 반환하고 제한된 후보 위치 또는 원래 위치를 사용한다. 기록을 조용히 숨기거나 넓은 구간 전체를 새 묶음으로 합치지 않는다. 이 한계에서는 겹침이 남을 수 있으며 전체 기록은 목록으로 접근한다. 진단에도 ‘밀집 한계’를 표시한다.
- 지도 이동 중에는 네이버 표식이 지도를 따라 움직이고, 멈춘 뒤 다시 묶는다. 화면 크기·패널 가림·선택 변경 시에도 배치를 갱신한다. 계산은 카메라를 이동시키지 않는다.

## 표현과 상태의 경계

`NaverGroupedMomentLayer`는 투영·공통 계산·네이버 표식 수명 관리를 공유한다. 한 호출에는 행동 또는 장면 한 종류만 전달한다. `MomentMarkerState.recordPin`은 행동 아이콘/건수/배경 점, `diaryPin`은 장면 순서/묶음 강조/배경 흐림을 지정한다. 행동과 장면의 개수 의미나 원본을 서로 섞지 않는다.

장면은 하나당 하나의 ID와 전체 일기에서의 순서를 전달한다. 지도에서 묶인 뒤 대표 번호와 `+추가 개수`를 그린다. 대표 번호는 열람 중인 장면을 우선하며 그 외에는 시간순 첫 장면이다. 기존 출발·도착 그림 함수에 배지를 추가하지 않고 전용 합성 그림을 사용한다.

## 기존 일기 연결

전체 `scenes`와 `DiaryReadingMemory.groupIds`를 분리한다. 지도 묶음을 누르면 기존 장면 패널에 그 구성원만 시간순으로 표시한다. 전체 장면 수·각 번호는 전체 일기를 기준으로 유지하고, 묶음에서 연 본문의 이전/다음은 그 묶음을 따른다. 본문에서 뒤로 가면 묶음 목록, ‘전체 장면’이나 시스템 뒤로 가기로 전체 목록에 복귀한다.

묶음 선택과 묶음 안의 본문 열람은 카메라/패널 높이를 바꾸지 않는다. 확대 후에도 선택했던 ID 집합을 유지하여 읽던 목록을 다시 쓰지 않는다. 다른 묶음을 직접 누르면 새 목록의 처음으로 이동한다. 전체 목록과 묶음 목록의 스크롤을 따로 보관하며 기존 읽기 북마크에 선택 묶음 ID와 스크롤을 추가한다. 옛 북마크도 읽을 수 있다.

삭제 시 최신 장면 집합과 교차하여 묶음을 갱신하고 전체 순서를 다시 표시한다. 빈 묶음은 전체 목록으로 돌아간다. 수정·삭제 확인·사진·원본 본문·동선 강조는 기존 기능을 사용한다. 기존 독립 행동 탐색 화면 및 5m 원본 행동 묶음까지 일괄 변경하지 않는다.

화면 밖 장면은 실제 배치된 말풍선의 사각형으로 판단하고 그 묶음의 모든 ID에 적용한다. 지도 이동 중에는 판정을 보류한다. 장면 로딩 전에도 카메라 이동·정지를 추적하고 처음 연결할 때 SDK의 정지 대기 상태를 읽어, 이미 멈춘 지도에서 판정이 계속 보류되지 않게 한다. 방향 화살표도 실제 표시 사각형을 피하도록 연결한다.

## 검증

관련 81개 테스트와 별도 미리보기 debug 빌드 통과. 공통 계산은 넓은 아이콘·선택 우선·입력 순서·경계·가림·이동 제한·공간 부족·동일 좌표·확대 분리·연쇄 방지를 검증한다. 일기 테스트는 전체 번호 유지·묶음 목록/본문/뒤로/삭제·패널 높이·기존 읽기 복원을 포함한다. 최종 리뷰에서 묶음에서 전체 목록 복귀 시 보류했던 스크롤 복원, 확대 후 열람 장면 우선 배치, 늦은 장면 로딩/이미 정지한 지도/이동·정지 리스너 해제를 추가 검증했다. 잠금 테스트를 약화하지 않았다.

Galaxy S25 가상 기록에서 장면 `2 +8` 선택 → 9개 목록 → 원래 본문 → 목록 복귀, 삭제 후 전체 14→13/묶음 9→8을 확인했다. 장면 선택 전후 50m 배율과 패널 상단 1493px이 유지됐다. 지도 확대 시 `2 +8`이 `2 +5`, `11 +2`로 나뉘어도 아래 9개 목록은 유지됐다. 행동 핀도 84건 선택 후 명시적인 구간 확대로 72/12 분리되는 것을 확인했다. 실기기 데이터는 가상 기록이며 실제 회원 기록을 변경하지 않았다.
