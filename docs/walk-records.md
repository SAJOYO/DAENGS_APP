# 산책 기록 입력과 보관

GPS가 불안정할 때 쓸 순수 계산 모듈과 검증 결과는 [행동 핀 위치 추정기](action-pin-estimator.md)에 있다.
버튼·Room 12·기한 복구·v2 동기화 연결은 [4단위 구현](action-pin-app-integration.md)에 있다. 서버 활성화와 실기기 확인은 별도다.

2026-09-05, [#144](https://github.com/SAJOYO/DAENGS_APP/pull/144). 서버 계약: [DAENGS_dev#251](https://github.com/SAJOYO/DAENGS_dev/pull/251).

## 사용자 흐름

산책 중 킁킁·배설·짖기는 GPS와 관계없이 누른 시각의 개별 기록을 저장한다. 정상 GPS는 원본을 유지하고 불안정하면 별도의 표시 핀을 추정한다. 좌표 근거가 없어도 목록에 행동을 남긴다. 반복 입력은 별개 기록이다. 저장 성공 안내에서 취소할 수 있다. 특별한 순간은 버튼을 누른 시점의 위치·시각에 자유 메모를 붙인다. 위치를 확보하지 못하면 메모만 저장한다. 대소변 선택, 감정/원인 분류, 사용자 정의 행동 목록은 없다.

후속 명세: [행동 즉시 저장·핀 위치 추정 연결 계약](action-pin-location-contract.md),
[APP #227](https://github.com/SAJOYO/DAENGS_APP/pull/227). 런타임 연결은 [APP #232](https://github.com/SAJOYO/DAENGS_APP/pull/232)에서 구현했다.

지도 마커 또는 '기록 N'에서 같은 상세창을 연다. 완료 직후와 지난 상세 모두 행동 종류/대상 정정, 메모 수정, 개별 삭제를 지원한다. 현재 마커는 기록별로 표시하며 가까운 기록을 펼치는 지도 클러스터 UI는 별도로 만들지 않았다. 동일 좌표에서 겹쳐 보여도 시간순 기록 목록에서 각 항목에 접근할 수 있다.

다견 기록은 대상 미지정이 기본이며 상세에서 고를 수 있다. 단일 반려견 동행은 그 아이를 기본 대상으로 저장한다. 특별한 순간은 산책 전체 메모다.

50m/1분 미달이어도 사용자 기록이 남았으면 세션을 보관한다. 운동량 집계 기준은 기존 값을 유지한다. 미종료 세션 복구 화면은 이번 변경에 포함하지 않았다.

일반 사진은 [PR #151의 사진 저장 정책](walk-diary-photos.md)에 따라 같은 일기 목록과 지도에서 열 수 있다. 사진은 Room v9의 별도 표와 영구 파일에 보관하며, 아래 행동/메모 동기화와 프로필 계약에는 포함하지 않는다.

## 저장과 계정

Room v7에서 도입한 `walk_entry`가 원본이다. v12는 기존 기록을 보존하며 핀과 동결 요청 상태를 더한다. payload와 서버 revision, mutation ID, dirty/error 상태를 보관한다. 사용자 결정으로 v6의 옛 행동 데이터를 비우고 새 vocabulary로 시작하며, 경로·산책 세션·동행 정보는 유지한다.

산책 소유 계정을 저장해 목록·전송 대상·편집을 분리한다. 미귀속 옛 로컬 기록을 다음 로그인 사용자의 기록으로 자동 업로드하지 않는다. 인증된 서버에서 같은 산책을 복원한 경우에만 소유권을 확인해 연결한다. 로그아웃 시 진행 중 기록은 종료를 요청하며 다른 계정에 이전 추적 화면을 표시하지 않는다.

## 동기화

경로 업로드/finalize와 별도로 entries PUT/DELETE/GET을 호출한다. 새 기록·변경·삭제는 Room에 먼저 남기고 WorkManager가 재시도한다. 서버의 원본 산책 ID가 있어야 기록을 전송할 수 있다. 전송 중 다시 수정하면 승인된 서버 revision만 전진시키고 새 내용을 유지한다.

409 충돌은 현재 로컬 내용을 유지하고 자동 재전송을 중단한다. 기록을 열면 충돌 안내를 보이며, 내용을 확인해 다시 저장하면 최신 서버 revision에 적용한다. 서버에서 이미 삭제한 기록은 로컬에서도 제거한다. 기록 목록은 Room 변경을 관찰하므로 서버 응답을 기다리기 위한 고정 1.5초 타이머가 없다.

## 산책 기록 프로필

`WalkRecordProfileApi`/모델은 서버의 `walk-record-profile-v0` 계약을 읽는다. 기록 수·기록이 남은 산책 수·근거를 제공하는 클라이언트이며 프로필 표시 화면은 아직 연결하지 않았다. 개인화 정책·성향 점수는 없다. 외부 주변 환경 수집과 일기/스토리보드 생성도 아직 연결하지 않았다.

## 확인 경계

단위 테스트는 Room 수정/삭제, 짧은 메모 보관, 계정 분리, 전송 중 수정 보존, 서버 삭제 반영과 기존 산책 경계를 검증한다. 실제 기기의 지도/키보드/알림 종료, 서버 배포 후 복원은 별도 확인이 필요하다. 서버 테이블을 적용하기 전에는 기록 API가 동작하지 않는다.
