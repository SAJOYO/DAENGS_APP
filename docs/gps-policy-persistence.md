# 산책별 GPS 정책 저장과 비교 (#313, 5-2 첫 단위)

산책 시작 때 동결한 `motion-v1` 정책을 기기에 저장한다. 속도 런타임과 완료 기록의
비교 계산이 같은 설정을 사용한다. #310의 신규 v1 핀 정책은 그대로다.

## 저장과 복원

- `WalkTrackingService.openSession`이 정책을 한 번 동결한다. 동일 객체를
  `WalkSpeedRuntime`에 넘기고, 버전·관측 스키마·설정 JSON·설정 해시를 포함한
  envelope를 `RecordedSession.motionPolicyJson`으로 writer에 전달한다.
- Room은 최초 세션 INSERT에 envelope를 같이 저장한다. 정책만 따로 뒤늦게
  저장하지 않으며, 같은 세션 ID의 재시작·서버 복원은 기존 정책을 덮어쓰지 않는다.
- Room 15→16은 nullable TEXT 한 칸만 추가한다. 사용자가 DB를 만들거나 팀원이
  별도 설정할 일은 없다. 앱 업데이트 후 DB를 열 때 자동 이관한다.
- 기존 산책과 정책 없는 서버 복원 산책은 `null/Legacy`다. 손상된 envelope,
  알 수 없는 버전·관측 스키마·설정·해시는 `Unsupported`이며 현재 기본값으로
  대체하지 않는다. 비교 실패를 0m의 정상 완료로 바꾸지 않는다.
- **관측 스키마 15와 Room 버전 16은 별개다.** 이번 변경은 GPS 원본의 형태를
  바꾸지 않으므로 `OBSERVATION_SCHEMA`를 올리지 않는다.

프로세스 종료 뒤 완료 journal을 읽을 수 있지만, 살아 있던 속도 표시를 복원하거나
산책을 자동 재개하지 않는다. 당시 정책이 존재한다는 것이 원본 저장 완료의 증거는 아니다.

## 완료 기록 비교

`RoomWalkFixLog.compareMotion(sessionId)`는 현재 소유자의 세션·정책·원본·epoch를
같은 DB 트랜잭션에서 읽고, 계산은 트랜잭션 밖 IO에서 수행한다. 반환 직전에 소유자를
다시 검사한다. 남의 세션이나 없는 세션은 `null`이다.

명시적 STOP, 모든 epoch의 drain·개수·원본 번호·source/clock/chain과 세션 종료
시각을 검증한 뒤 `RecordedMotionComparison.Ready`를 반환한다. 여기에는 기존 거리·
활동 시간, 후보 거리·구간 수·기록 시간, 정책 버전·설정 해시와 두 계산의 60초/50m
통과 여부가 있다. 결손·미지원 정책·미완료 원본은 이유가 있는 `Unavailable`이다.

기존 시간은 같은 chain의 첫/마지막 fix 사이를 더하고, 후보 시간은 닫힌 활동 구간을
더한다. 따라서 첫 fix 전 대기나 마지막 fix 후 STOP까지의 시간 때문에 산책 인정
결과가 달라질 수 있다. 후보 시간을 실제로 걸은 시간으로 표현하지 않는다.

이 조회는 요청할 때만 계산하는 개발용 진단 경로다. 일반 산책마다 이중 계산하거나
비교 결과를 저장·업로드하지 않는다. 사용자용 비교 화면은 추가하지 않는다.

## 적용 범위와 다음 전환

현재 거리·경로·요약·기록 유지/삭제는 계속 기존 `TrailRecorder/summarize`를 쓴다.
정책이 저장됐다는 이유로 후보 거리나 v2 핀을 활성화하지 않는다. 다음 전환에서는
거리·경로·요약을 같은 계산으로 연결하고, 60초/50m의 차이와 기존 핀·사진·전송
경계를 확인해야 한다. 서버의 거리 계산도 이번 변경의 대상이 아니다.

정책 envelope 및 단조 시각·속도·epoch 전체의 **서버 백업은 현재 API 계약에 없다.**
다른 기기로 복원한 기록에 당시 정책이 있다고 가정하지 않는다. 기존
`gps-recording-v1`의 `recordingEligible` 저장 증명과는 다른 범위다.

## 검증 경계

기존 테스트 클래스에 사례를 더했다. `RecordingJournalTest`는 실제 SQLite 파일을
닫고 다시 열어 정책·원본·완료 증거·재시도 보존과 소유자 경계를 검증한다.
`WalkMigrationTest`는 이전 버전들과 15에서 최신으로 이관할 때 기존 공개 보드와
v1/v2 핀·대기 요청을 보존하는지 확인한다. `WalkSpeedServiceTest`는 실제 서비스가
정책을 저장하고 같은 해시를 런타임에 사용하는지 확인한다.

`MotionPolicyTest`, `RecordedMotionReplayTest`, `WalkSpeedRuntimeTest`는 손상/미지원
구분, 사용자 설정 보존, 개별/배치 입력과 일시정지·빈 STOP의 재생 일치 및 60초/50m
주변의 비교를 담당한다. 실기기 GPS 정확도·장기 성능·배터리 검증을 대신하지 않는다.

2026-09-11, dev `7c04dcc0` 기준 debug 빌드와 선택 9개 클래스의 81개를 실행했다.
최초에는 새 envelope의 자동 serializer가 생성되지 않아 8개가 실패했다. 앱의 기존
방식에 맞춰 명시적 JSON 변환으로 수정한 뒤 영향받는 5개 클래스 28개와 debug 빌드를
다시 실행해 모두 통과했다. 변경하지 않은 나머지 4개 클래스 53개는 최초 통과 결과를
유지한다. 최종 실패·오류·skip은 0개다. 전체 테스트·과금 CI·실기기 설치는 수행하지 않았다.
