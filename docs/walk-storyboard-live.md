# 실제 산책 장면 분석

로그인한 회원의 산책을 종료하면 기존 업로드 작업이 GPS finalize → 행동·메모 동기화
→ 스토리보드 분석 순서로 진행한다. 산책 상세 → 스토리보드 검토에서 결과를 확인한다.
`장면 분석 · 다시 시도`로 복구할 수 있고, 최신 결과가 있는 상태에서는 환경을 다시 읽는다.
분석 실패는 WorkManager가 재시도하며 원본 산책은 보존한다. AI 생성은 아직 연결하지 않는다.

서버는 geo에서 이식한 관측·선택 규칙으로 장면을 만들고 Place에 선택한 지점 주변만
조회한다. 환경 조회가 실패해도 자료 미확인 장면과 관측 기록을 돌려준다. 여가 시설·카페·
음식점 등록 위치와의 거리이며 산책 당시 상황·방문·행동 원인을 뜻하지 않는다.

문구 편집·숨김·검토 완료 스냅샷은 기존대로 별도 보관한다. 원본 핀·메모 정정/삭제 시
동기화를 다시 예약하고, 새 장면이 도착하면 사용자 문구는 남긴 채 재확인을 표시한다.
최신 분석을 기다리는 동안 이전 환경 장면을 최신 결과로 표시하거나 검토 완료하지 않는다.
재요청·통신 실패·취소·서버의 비완료 응답은 마지막 정상 bundle을 지우지 않는다. 현재 기록과
같은 원본에서 만든 사본이면 이전에 저장한 장면이라는 안내와 함께 열람·문구 편집을 유지한다.
새 요청이 성공하기 전에는 검토 완료를 막는다. 핀 수정·삭제나 동기화 충돌로 원본이 달라졌다면
이전 bundle은 보관만 하고 현재 기록 화면에 합치지 않는다. 재시도 성공 후 새 결과로 교체한다.
로그인하지 않은 로컬 산책은 기존 직접 기록 검토를 계속 제공한다.

Room 9→10은 `walk_scene_analysis`만 추가하고 경로·사진·사용자 검토본을 보존한다.
Room 10→11은 마지막 정상 bundle의 `bundleEntryStamp`를 추가한다. 기존 ready 결과의 stamp를
이관하며, 최신 요청의 status/entryStamp/generation과 정상 bundle의 원본을 구별한다.
분석 응답은 계정·로컬 기록 stamp·서버 generation을 트랜잭션에서 대조한 뒤 저장한다.
현재 요청과 다른 세션·합성 결과·과거 generation·입력 정정 중 도착한 결과는 채택하지 않는다.
앱에서 아직 보내지 못한 기록이나 충돌이 있으면 먼저 그 기록을 맞춘다.

필요한 서버 계약: DAENGS_dev `docs/walk-storyboard-live.md`.
서버의 `20260905_walk_storyboards.sql` 적용 및 기능 배포가 선행되어야 한다.
기존 debug `geo 스토리보드 실험`은 합성 JSON용 독립 화면으로 유지한다.
